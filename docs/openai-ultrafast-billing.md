# OpenAI 账号级 UltraFast 档位计费

部分兼容上游会把账号下所有模型固定服务为 UltraFast，即使客户端没有发送 `service_tier`，也会在响应中声明 `"service_tier":"ultrafast"` 并收取相应费用。只有按请求档位结算会导致这种账号少计费用。

## 开启位置与作用范围

在管理后台「账号管理」新增或编辑 **OpenAI / API Key** 账号，开启 **UltraFast 档位计费**。默认关闭，配置保存在账号 `extra`：

```json
{
  "openai_response_tier_billing_enabled": true
}
```

这是所选上游账号的响应档位结算开关，覆盖该账号下所有有基础价卡的 token 模型，无需逐个模型添加 UltraFast 价格。开关随账号配置保存，并保留在完整、精简调度缓存中。OAuth 账号和其他平台不启用这项响应升档策略。

开关只控制结算，**不会强制改写出站请求，也不保证上游提供加速**。开启前应确认该上游的响应档位声明与收费约定。

自营 Codex OAuth 中转透传 `default`、导致下游 Fast 降价的情况，使用[可信 OAuth 中转 Fast 兼容选项](openai-oauth-relay-fast-billing.md)。本响应档位计费开关优先级更高，两种上游约定不应同时开启。

## 档位如何选择

开启后，优先使用上游返回的已知 `service_tier`。Responses 流式请求使用终态事件；终态只返回档位、不重复 `model` 时也能识别。非流式和 Chat Completions 响应读取响应中声明的档位，非终态 Responses 事件中的请求回显不作为实际档位。

缺失或未知响应档位时，保留最终出站请求的档位并记录告警；不会仅因开关开启就猜测为 UltraFast。`fast` 响应归一为 `priority`。明确的较低响应档位也会影响结算。

| 开关 | 请求档位 | 上游响应档位 | 最终结算档位 |
| --- | --- | --- | --- |
| 开 | 未提供或 `priority` | `ultrafast` | `ultrafast` |
| 开 | `ultrafast` | `default` | `default` |
| 开 | `priority` | 缺失或未知 | `priority` |
| 开 | 未提供 | 缺失或未知 | 普通档 |
| 关 | 未提供或 `priority` | `ultrafast` | 保留请求档位，不自动升档 |
| 关 | `ultrafast` | `ultrafast` 或缺失 | `ultrafast` |

**客户端明确请求 UltraFast 且最终仍按 UltraFast 结算时，仍应用模型的 UltraFast 倍率，与这个账号开关是否开启无关。** 关闭开关不表示客户端可以按普通价格使用 UltraFast。原有可采信的响应降档规则继续生效。

## token 费用、缓存和倍率

最终结算档位为 `ultrafast` 时，输入、输出、缓存读取、缓存写入分别按模型对应的**标准单价 × UltraFast 倍率**计算，再应用有效用户/分组倍率和账号的分组倍率。GPT-6.2 Sol/Astra 在 2027-03-01 00:00（太平洋时间，08:00 UTC）前使用 3 倍促销价，之后使用 6 倍；以请求的 `PricingAt` 为准，延迟结算不会改用结算时刻。其他模型默认 6 倍。渠道显式 `ultrafast_multiplier` 优先，分组免费 UltraFast 继续向客户按 Standard 重新计价。UltraFast 不叠乘 Fast/priority 单价或自定义 Fast 倍率。

GPT-6.2 Sol/Astra 默认价卡在输入上下文严格超过 272,000 token 时，对整次请求的输入、缓存读写乘 2，输出乘 1.5；仍受账号/分组长上下文开关控制。OpenAI OAuth/Setup Token 的 GPT-6.2 Sol/Astra、GPT-6.1 Sol/Terra 豁免模型长上下文附加费，API Key 不豁免。GPT-6 Astra 没有订阅豁免。显式渠道区间价格仍优先，缓存读写计入输入上下文。OpenAI 总输入拆成普通输入、缓存读、缓存写三个互斥桶，避免同一缓存 token 同时按普通输入收费。显式配置为零的缓存写价仍为零。

例如 GPT-6.2 Sol 在促销期按标准价及已适用的上下文规则算出的费用为 `$1`，最终 UltraFast，分组倍率 `0.25`，账号的分组倍率 `1`，客户费用为 `$1×3×0.25×1=$0.75`；促销结束后为 `$1.50`。账号的独立**成本统计倍率**不参与客户余额的这一公式。用户专属倍率、高峰定价及模型附加费等既有配置仍然有效。

日志实扣、余额、Key 配额及时间窗口沿用现有统一扣费命令和金额精度。持久扣费完成后失效相应余额/额度缓存，由数据库回填；本开关没有新增第二条扣费路径。

本改动统一的是 token 模型的 UltraFast 价格；按次、图片、视频、音频及工具调用的单独计量规则保持现状。有价卡才有可计算的模型标准费用，本开关不会为未知模型自动生成基础价。

## 兼容性

本次策略对齐无需数据库迁移，历史账单不会重算或补扣。新请求按上述模型、请求时间和凭据类型结算；回退旧二进制会恢复旧策略。在混合版本集群中，各节点可能产生不同金额，应在部署时统一版本。远程目录、显式价格覆盖及运营折扣仍保留，源码默认值不代表生产配置已经更新。上游没有 `gpt-6.2-astra-pro` 的独立计费规则，该 fork 模型保留既有价格，不自动获得 Sol/Astra 的促销或订阅豁免。

响应档位结算日志包含请求档位、响应档位、结算档位和缺失标识回退信息，用于核对上游结算约定；不会记录 API Key 或请求正文。档位标识与 TPS 是不同指标，是否达到某个生成速度不由本开关保证。
