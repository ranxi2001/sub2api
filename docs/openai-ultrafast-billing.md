# OpenAI 账号级 UltraFast 档位计费

部分兼容上游会把账号下所有模型固定服务为 UltraFast，即使客户端没有发送 `service_tier`，也会在响应中声明 `"service_tier":"ultrafast"` 并收取相应费用。只有按请求档位结算会导致这种账号少计费用。

## 开启位置与作用范围

在管理后台「账号管理」新增或编辑 **OpenAI / API Key** 账号，开启 **UltraFast 档位计费**。默认关闭，配置保存在账号 `extra`：

```json
{
  "openai_response_tier_billing_enabled": true
}
```

这是所选上游账号的响应档位结算开关，覆盖该账号下所有有基础价卡的 token 模型，无需逐个模型添加 UltraFast 价格。开关随账号配置保存，并保留在完整、精简调度缓存中。OAuth 账号和其他平台不启用这项响应升档策略。

开关只控制结算，**不会强制改写出站请求，也不保证上游提供加速**。开启前应确认该上游的响应档位声明与收费约定。

## 档位如何选择

开启后，优先使用上游返回的已知 `service_tier`。Responses 流式请求使用终态事件；终态只返回档位、不重复 `model` 时也能识别。非流式和 Chat Completions 响应读取响应中声明的档位，非终态 Responses 事件中的请求回显不作为实际档位。

缺失或未知响应档位时，保留最终出站请求的档位并记录告警；不会仅因开关开启就猜测为 UltraFast。`fast` 响应归一为 `priority`。明确的较低响应档位也会影响结算。

| 开关 | 请求档位 | 上游响应档位 | 最终结算档位 |
| --- | --- | --- | --- |
| 开 | 未提供或 `priority` | `ultrafast` | `ultrafast` |
| 开 | `ultrafast` | `default` | `default` |
| 开 | `priority` | 缺失或未知 | `priority` |
| 开 | 未提供 | 缺失或未知 | 普通档 |
| 关 | 未提供或 `priority` | `ultrafast` | 保留请求档位，不自动升档 |
| 关 | `ultrafast` | `ultrafast` 或缺失 | `ultrafast` |

**客户端明确请求 UltraFast 且最终仍按 UltraFast 结算时，也按6倍收费，与这个账号开关是否开启无关。** 关闭开关不表示客户端可以按普通价格使用 UltraFast。原有可采信的响应降档规则继续生效。

## token 费用、缓存和倍率

最终结算档位为 `ultrafast` 时，输入、输出、缓存读取、缓存写入分别按模型对应的**标准单价×6**计算，再应用有效用户/分组倍率和账号的分组倍率。UltraFast 不套用 Fast/priority 单价或自定义 Fast 倍率后再乘6；Fast/priority 仍使用独立规则。

长上下文按既有模型或分组价卡规则处理，缓存读写计入输入上下文。OpenAI 总输入拆成普通输入、缓存读、缓存写三个互斥桶，避免同一缓存 token 同时按普通输入收费。显式配置为零的缓存写价仍为零。

例如按标准价及已适用的上下文规则算出的费用为 `$1`，最终 UltraFast，分组倍率 `0.25`，账号的分组倍率 `1`，客户费用为 `$1×6×0.25×1=$1.50`。账号的独立**成本统计倍率**不参与客户余额的这一公式。用户专属倍率、高峰定价及模型附加费等既有配置仍然有效。

日志实扣、余额、Key 配额及时间窗口沿用现有统一扣费命令和金额精度。持久扣费完成后失效相应余额/额度缓存，由数据库回填；本开关没有新增第二条扣费路径。

本改动统一的是 token 模型的 UltraFast 价格；按次、图片、视频、音频及工具调用的单独计量规则保持现状。有价卡才有可计算的模型标准费用，本开关不会为未知模型自动生成基础价。

## 兼容性

无需数据库迁移。历史账单不会重算或补扣。**最终按 UltraFast 结算的 token 请求统一改为6倍**：此前使用通用2倍规则的模型会受影响，包括未开启响应档位结算、但客户端明确请求 UltraFast 的账号。这一价格变化与默认关闭的响应识别开关是两个层面的行为。

响应档位结算日志包含请求档位、响应档位、结算档位和缺失标识回退信息，用于核对上游结算约定；不会记录 API Key 或请求正文。档位标识与 TPS 是不同指标，是否达到某个生成速度不由本开关保证。
