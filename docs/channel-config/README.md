# 渠道配置

`/admin/channel-config` 统一渠道管理、利润运维和账号运维。面板首次展开才挂载，利润面板折叠后保留结果与筛选；账号面板折叠时停止定时读取。旧 `/admin/channel-operations`、`/admin/upstream-channels`、`/admin/profit-operations`、`/admin/account-ops` 跳转到对应面板，保留 query 和 hash，继续要求管理员权限。

名称 / URL / 账号归属与模型定价、供应商连接、利润成本来源分别配置。从渠道成员入口选择当前渠道，或在顶部输入渠道 ID；利润下钻的渠道和账号继续用于账号规则筛选。运营分组、通知渠道、OAuth 和独立账号规则保留原配置，并不按域名合并。

新增供应商默认“倍率估算”。迁移前已有供应商保留“钱包消费”；名称或账号归属编辑不修改该选择。在供应商连接面板单独切换成本来源时，以 revision 做并发检查。钱包读数缺失仍是 null / 不可用，展示查询窗口、读取时间和失败原因，不回填零。不修改用量或扣费流水、采购倍率。回滚旧二进制会忽略 cost_mode 并重新按原钱包逻辑统计，应先评估口径变化；新增列可以保留。

利润首次读取仍进行完整窗口聚合。之后相同筛选与维度下的分页、排序复用两分钟内的汇总，显示原 queried_at。各进程最多保留 8 份、每份 4 MiB，超过 10,000 个维度/成员/质量记录时退回原分页查询；不会缓存请求正文。并发相同窗口合并计算，失败不缓存，取消会取消发起者的查询。刷新统计清除本进程缓存；刷新钱包同时重新探测。成本模式保存清除本进程缓存，其他节点最多保留两分钟旧结果。配置编辑提示刷新，未宣称第一遍百万行聚合已加速。

验证由 PR CI 执行：`TestProfitOperationsCachePagesSortAndInvalidation` 对同一窗口首次、翻页、倒序、缺失金额排序进行对照，前三次读取只调用聚合一次；这是合成聚合调用次数证据，不是生产延迟基准。`TestProviderProfitNamingPreservesEstimateUntilWalletOptIn` 在非空 PostgreSQL 用量窗口验证命名不改变请求数/收入/成本来源，选择钱包且没有读数时成本为 null。浏览器截图使用实际 Vue 组件与合成 API 数据，不访问生产或发送收费请求。
