# 账号运维：供应商余额与多人通知

在 `/admin/account-ops` 配置账号运营分组、提醒阈值与收件人。

- API Key：同一供应商使用一份平台余额。新导入且尚未分组的 Key 按保存的供应商 ID 自动归组；已有手动分组和明确的未分组状态保持不变；已有账号可在分组编辑中选择供应商。没有关联供应商的组继续使用首个账号的余额。
- 供应商余额、币种和更新时间来自渠道运维现有目录，不重复登录上游，也不把不同 Key 的额度相加。缺失、失败或过期的数据不会退回 Key 额度，也不算零余额或恢复。手动刷新样本一小时内有效；开启定时刷新时使用两倍刷新间隔判断过期。
- 供应商的余额采集及刷新在 `/admin/channel-operations` 管理；外发通知阈值、告警/恢复通知开关在账号运维管理。阈值单位须与供应商原始币种一致，不隐式换算人民币或 USD。渠道目录原有低余额标记保留，外发通知复用账号运维的事件与投递队列。
- 每组每次告警/恢复产生一个事件。每个收件邮箱收到一份；地址去重，成功的邮箱不会因其他邮箱失败而重发。关联供应商且已设置余额阈值时，不再因组内 Key 的余额不足响应额外产生重复告警。
- 最多 10 个收件邮箱，可用换行、逗号或分号分隔。邮件分别发送，投递结果分别保存；Webhook 沿用现有配置。
- OAuth 分为“速抛／临时号”和“长期号”。旧账号默认临时号，管理员可逐个修改。分类只修改 `extra.oauth_lifecycle`，不改变凭据、调度或清理策略，不因 access token 到期自动删除账号。

这是基于 #850 的后续功能，不创建另一份供应商目录、刷新任务或数据库迁移。供应商删除或余额查询失败后，关联组显示未知数据；必须重新关联有效供应商或切回账号采集，不能继续用旧平台余额发送新告警。

旧单邮箱配置直接兼容。新版本将多个地址规范化到现有 `recipient` 字符串字段；回滚到只支持单邮箱的旧版本前，应先改为单邮箱并解除供应商余额关联。OAuth 用途字段是附加元数据，旧版本会忽略它。
