# 多 TOTP 验证器恢复边界

Refs #881。本页描述首个诊断修复检查点，尚未完成 factor 绑定与恢复方案。

本地托管 Worker 的 enroll/activate 流程新增验证器，没有撤销旧验证器。
新旧密钥都被登录协议接受时，任务保持 `uncertain` 并保留候选密钥，
普通登录配置不会自动切换。状态 API 的 `error_code` 区分以下结果：

| 错误码 | 已观察到的结果 | 未证明的事项 |
| --- | --- | --- |
| `new_accepted_old_valid` | 本次先验证候选密钥成功，随后旧密钥也被接受 | 尚无持久化 factor 绑定，未撤销旧验证器 |
| `old_accepted_new_valid` | 恢复检查先接受旧密钥，随后候选密钥也被接受 | 尚无持久化 factor 绑定，未撤销候选验证器 |
| `verification_failed` | 验证未获得足够成功证据 | 不能据此断言候选无效或旧验证器已撤销 |

这些诊断不是成功替换或撤销的证明。不要再次 enroll 来消除不确定状态，
不要删除唯一可用验证器。已有账号可通过现有管理员恢复导出接口获取候选
或旧凭据；导出只提供恢复材料，不证明该密钥可完成登录。妥善保护导出材料。
旧账号删除后的任务访问和重新导入路径仍待实现，不能把重新添加账号当作
清除原任务或重新 enroll 的依据。
