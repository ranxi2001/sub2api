# 利润运营与独立上游渠道归属

利润运营页 `/admin/profit-operations` 按独立上游渠道实体聚合请求、收入与估算利润。渠道实体具有不可变内部 ID、唯一且创建后不变的 code、唯一可编辑名称和备注；账号使用独立 FK 显式归属。

账号归属不由 URL 派生。同一渠道可包含不同 URL、无效/未知 URL、动态 OAuth 或不支持读取 URL 的账号；不同渠道也可包含相同 URL。只有当前未绑定账号才按现有安全有效 URL 自动聚合，无法识别时保留 unknown。利润筛选与下钻使用实体内部 ID，不受 URL、名称和分页位置变化影响。

`/admin/upstream-channels` 管理实体与分页成员；账户管理支持创建时绑定、编辑、批量选择。一次绑定最多 100 个明确账号，页面展示受影响账号并要求确认，写入使用 revision CAS 后 GET 读回。修改渠道成员会递增渠道 revision，旧确认失效。

删除有成员的渠道一律冲突。管理员须先在成员页明确选中有界账号并确认解绑、重新读取版本后，才可删除空渠道。关联表外键禁止渠道级联删除；解绑只改变当前归属，不修改账号路由、历史 usage 或账本。软删除账号保留绑定与历史请求归属；真正物理删除时仅清除其绑定，migration 313 触发器推进原渠道 revision。归属报表是当前配置，不代表历史路由快照。

## 财务口径

估算成本 = 保存的 `usage_logs.total_cost` × 当前账号统一成本倍率 `extra.cost_multiplier`；未保存时沿用既有调度默认 0.1。请求收入 = 已保存 `actual_cost`；估算利润 = 收入 − 估算成本。账号扣费倍率、模型价卡成本和账本结算不再叠加。代码不改变该利润公式。

标准收费基数与收入均按历史保存值展示，不按当前价卡重算。订阅计价不等于现金收入；未知 URL/动态路由不虚构归属。若缺少有效金额/倍率，汇总按既有逻辑显示未知。

Migration 312 创建 `upstream_channels` 与 `upstream_channel_bindings`；不按 URL、展示名称或历史 usage 猜测实体关系。早期分支中的 URL-key 备注表、API 和 UI 已从本 PR 删除，因此 URL 只用于未绑定账号的只读自动归类，不是可编辑渠道身份。

验收和变更记录见 [PROGRESS.md](../PROGRESS.md)。

## 大数据量查询

利润快照的服务端查询预算为 5 分钟，页面等待上限为 5 分 30 秒，独立于其他管理接口的默认超时。等待期间页面保持汇总状态；切换查询或离开页面仍会取消旧请求。反向代理的读取超时应至少为 330 秒，避免先于应用中断响应。

统计只投影计算所需的用量字段，保留完整时间范围、精确合计和延迟分位数。分页仍只限制展示条数，不截断统计样本。超出查询预算时接口返回 HTTP 504 和 `PROFIT_OPERATIONS_TIMEOUT`，页面明确显示统计超时，不将未完成结果显示为零。
