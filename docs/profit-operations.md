# 利润运营与独立上游渠道归属

利润运维页 `/admin/profit-operations` 按渠道显示本站请求的收入、成本、毛利润和毛利率。在「服务商管理」添加供应商后，无须再手建同名渠道；原有手工渠道仍可用。筛选和下钻使用渠道内部 ID，不按显示名称识别。

例如周一开始手填 A 的网址和 Key、周五才登记 A：重新查询含周一的时段，原网址行里没有其他明确归属的请求会归入 A，不需要重新导入 Key，也不会在两行重复计数。这是报表分组，不改账号路由和历史用量。没有逐笔历史网址时，用原网址行的当前有效配置来认领。明确绑到**另一个**渠道的账号仍归该渠道。手动把渠道解成空（`channel_id` 为空）之后，若网址仍只对应一个服务商，请求回到该服务商，不再单独留下「未绑定 · URL 自动归类」行。两个服务商共用同一个站点键时不自动合并。只有唯一的 HTTPS 站点根地址或其 `/v1` API 地址参与认领，不把其他租户路径、动态或无法确定的地址并成同一站。`unknown:oauth_dynamic_endpoint`（页面上可能显示为未知上游）没有稳定网址，只按供应商导入、`provider_binding` 或已有渠道绑定归类；没有任何这种关联时才留在未知行。

`/admin/upstream-channels` 管理实体与分页成员；账户管理支持创建时绑定、编辑、批量选择。一次绑定最多 100 个明确账号，页面展示受影响账号并要求确认，写入使用 revision CAS 后 GET 读回。修改渠道成员会递增渠道 revision，旧确认失效。

删除有成员的渠道一律冲突。管理员须先在成员页明确选中有界账号并确认解绑、重新读取版本后，才可删除空渠道。关联表外键禁止渠道级联删除；解绑只改变当前归属，不修改账号路由、历史 usage 或账本。软删除账号保留绑定与历史请求归属；真正物理删除时仅清除其绑定，migration 313 触发器推进原渠道 revision。目录、成员、质量和容量描述当前配置。财务事件优先使用冻结证据，再看事件当时的手工或导入归属；缺乏同期记录的旧手工渠道仅作兼容估算。

## 财务口径

- **已绑定供应商：**打开利润页会先按**所选窗口**刷新每个已关联服务商的钱包消费，再用与该窗口起止时间相同的快照计算成本。快照存在 `provider_spend_snapshots`（`provider_id`、`window_from`、`window_until`、`amount`、`currency`、`observed_at`、`source`）。同一窗口约 2 分钟内已成功读过的快照会复用；页面上的「刷新此时段上游消费」会忽略这 2 分钟。失败时保留该窗口上一次成功的金额；若从未成功，成本不可用，并显示错误和时间。这个数字可能包含不是本站产生的支出，仍然整笔使用，不按本站请求拆开，也不再用逐笔上游账单。只有 USD 才与本站请求收费相减。
- **今天和其他时段：**北京时间当天的窗口（从当天 0 点开始，结束于当前时刻附近约 5 分钟内，或直到次日 0 点）会同时更新渠道运维的「今日消费」（`mature_providers.metrics.today_spend`）。昨天、上周和自定义区间只写入对应窗口的快照，**不会**覆盖「今日消费」。没有窗口快照时，利润报表只在当天窗口回退到仍有效的「今日消费」。New API 请求 `/api/log/self/stat?type=2&start_timestamp=&end_timestamp=`，时间就是所选窗口。Sub2API 的当天仍请求 `/api/v1/usage/dashboard/stats`，优先 `today_actual_cost`，否则 `today_cost`，币种记为 USD。其他时段请求 `/api/v1/usage/dashboard/snapshot-v2?start_date=&end_date=&timezone=Asia/Shanghai`，汇总返回里的 `actual_cost`（优先趋势，否则模型），不用标价 `cost` / `total_cost`。该日期接口按北京时间的整天计算；窗口若不是整天，读到的是覆盖这些日期的日历日合计。较旧的 Sub2API 站点如果没有 `snapshot-v2`，该时段成本不可用，并保留已有快照。查询接口不接受比现在晚超过 1 分钟的结束时间。
- **下钻：**按账号或模型比较，或筛选账号、分组、模型时，不把钱包总额按比例分到每一行。钱包成本留在渠道合计；这些子集的上游成本显示不可用。
- **未绑定供应商：**包括只有手工渠道 ID、没有对应窗口钱包读数的渠道。估算成本 = 保存的 `usage_logs.total_cost` × 当前账号成本倍率 `extra.cost_multiplier`；未设置倍率时用 0.1。显式零倍率与缺少有效倍率不是一回事。上游刷新失败不会挡住这些估算行。
- **两种渠道：**请求收入取本站已保存的 `usage_logs.actual_cost`，订阅计价不等于现金收入。毛利润 = 收入 − 成本，毛利率 = 毛利润 ÷ 收入。明确的零价按零算，收入为零时不显示百分比。跨渠道合计先按各自口径计成本，再按总收入算毛利率，不平均每行百分比。同一窗口里，已绑定渠道用各自的钱包快照，未绑定渠道用倍率估算，再相加。

打开利润页会为当前窗口刷新（或复用刚读过的）钱包快照，然后计算毛利润；页面显示最近一次成功读取的时间。打开渠道运维会自动刷新一次已保存登录态的服务商，更新卡片上的「今日消费」。两条路径都走渠道运维原来的探测会话，不会比那次探测更频繁地更换令牌，也不会把令牌或密文写进日志。页面不再提供「同步上游账单」。旧的逐笔同步代码可以留在仓库里，但不再决定本报表的成本。遇到 HTTP 429 时沿用利润同步的退避，不把不完整的读数写成新金额。

## 服务商对账与隔离试用

仅在测试实例上从源码构建此分支；使用独立的 PostgreSQL、缓存、模拟上游及虚构 Key，不要指向生产服务。先保留测试库副本，再按项目正常启动流程应用迁移 383–387；回退测试环境请恢复副本，不要手工删除业务表。打开利润页或渠道运维会按上面的规则向已保存的服务商读取钱包，不会逐笔拉取 `/api/v1/usage`。离线用例通过模拟 HTTP 传输提供上游响应；管理页面的实际连接仍要求受控的公网 HTTPS 测试站，不能用 localhost，也不要为试用关闭地址校验。

1. 给手填网址和 Key 的测试账号记两笔虚构请求，再在服务商管理添加同网址的 A。选择含这两笔请求的日期，确认两笔只出现在 A 下；不更动账号，也不等下一笔请求。
2. 打开利润页并选择北京时间当天。A 的上游成本等于刚读到的当天钱包消费，即使另有逐笔账单或共享钱包里的其他支出。把窗口换成昨天或其他区间时，使用该区间自己的快照；没有快照时成本不可用，不能把今天的数字填进去。今天的「今日消费」也不会被昨天的金额覆盖。
3. 登记日期不是查询起点。没有逐笔请求标识的历史请求仍可归到 A，但不会因此生成一笔虚构的逐笔成本。按账号或模型下钻时，渠道合计仍是整笔窗口消费，每一行不显示分摊金额。手动解除 A 的渠道绑定后，只要网址仍然只属于 A，这些请求回到 A，而不是单独的未绑定网址行。

验收例：本站两笔收入合计 100，当天钱包消费为 60 USD。即使上游用量明细是 32 和 13、另有余额实扣，主表也应为 **成本 60、毛利润 40、毛利率 40%**。同一钱包不会按两笔请求各计一次。另一个未绑定供应商的手工渠道仍按倍率估算；和 A 加总时，成本是 60 加上该渠道的估算。钱包消费为 0 时成本是 0，而不是不可用。昨天若有匹配的 15 USD 快照，则该窗口成本是 15，而不是 60。

测试数据不要用真实客户请求标识、令牌、站点地址或钱包截图。原版利润运维的验收记录见 [PROGRESS.md](../PROGRESS.md)。

## 大数据量查询

利润快照的服务端查询预算为 5 分钟，页面等待上限为 5 分 30 秒，独立于其他管理接口的默认超时。等待期间页面保持汇总状态；切换查询或离开页面仍会取消旧请求。反向代理的读取超时应至少为 330 秒，避免先于应用中断响应。

统计只投影计算所需的用量字段，保留完整时间范围、精确合计和延迟分位数。分页仍只限制展示条数，不截断统计样本。超出查询预算时接口返回 HTTP 504 和 `PROFIT_OPERATIONS_TIMEOUT`，页面明确显示统计超时，不将未完成结果显示为零。
