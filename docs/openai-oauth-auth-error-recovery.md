# OpenAI OAuth 认证错误与调度恢复

OpenAI OAuth 账号收到认证错误后进入 `status=error`。错误状态会阻止普通调度、粘性会话复用和母账号凭据供影子使用；处理错误时仍会通知运行时阻断器、刷新调度快照并写入 outbox。

认证失败保留数据库中当前的 `schedulable` 开关。普通编辑错误账号也保留该开关，避免编辑时的旧快照覆盖后来执行的手动或定时操作。队列重登成功后恢复 `active`、清除错误和临时冷却，同时保持当前调度开关。

普通编辑未显式提交 `status` 时，保留数据库当前的 `status` 与 `error_message`。账号编辑表单仅在管理员实际改变状态选择时提交该字段。即使编辑表单在 401 之前读取了 `active`，随后保存无关设置也不能清除认证错误；重登已经完成时，旧错误快照同样不能重新覆盖恢复状态。显式修改账号状态继续沿用原有管理接口行为。

| 认证错误前的状态 | 错误期间 | 重登成功后 |
| --- | --- | --- |
| 已开启调度 | `error`，开关仍为 true，不可被选中 | `active`，恢复调度 |
| 因 429 暂停 | `error`，开关仍为 false | `active`，继续暂停 |
| 手动、定时或准入流程暂停 | `error`，开关仍为 false | `active`，继续暂停 |

“遇到 429 关闭调度”仅在实际收到 429 时关闭开关，启用这个配置本身不应阻止 401 后恢复。重登过程中发生的手动、定时或 429 开关变更，以数据库最新值为准。重登的任务所有权与凭据快照 CAS 保持原有校验。

## 升级与回滚

无需新增配置或数据库迁移。其他平台以及 OpenAI API Key 的 `SetError` 继续沿用关闭调度开关的行为。

旧版本已经把 `schedulable` 写成 false 的账号不会在升级时被自动开启；仅凭当前值无法区分认证停用、手动暂停和 429 暂停。确认账号认证已恢复且应当接收请求后，通过原生账号调度开关恢复。升级本身不触发真实重登或模型请求。

回退二进制不需要撤销数据库结构，但旧版本会重新在认证错误时关闭开关，并可能在重登后留下暂停状态。混用新旧版本期间，旧进程仍可能写入这种状态；应按实际运行版本检查，不能把源码合并视为线上恢复。
