# Serverless 地区到 Pod 路由

入口：设置 → 网关服务 → Serverless 管理。默认关闭，无独立侧栏。首期管理已有 gateway Pod 的自动注册、健康、地区绑定及入口流量统计，不创建、删除或扩缩容 Kubernetes 资源。

## 接入

主站和 gateway 使用同一 PostgreSQL/Redis，并通过 Secret 注入同一个至少 32 字节的 RUNTIME_SERVERLESS_SECRET。不要把真实密钥写入配置示例、日志或表单。

gateway 额外配置 RUNTIME_ROLE=gateway、RUNTIME_SERVERLESS_ID=nerd-us-1、RUNTIME_SERVERLESS_ENDPOINT=https://pod.example.com、RUNTIME_SERVERLESS_REGION=US。主站只需设置集群密钥。逻辑 ID 全局唯一，进程每次启动获得新实例标识；同 ID 的新进程不能覆盖仍有新鲜心跳的旧实例。

endpoint 必须由主站可达，并固定到指定实例，不能指向随机负载均衡的 Service。跨集群 Pod/ClusterIP 通常不可达，应使用专属 HTTPS 入口或受信隧道；HTTP 只接受私网/loopback IP。反向代理须同时转发 /internal/serverless/probe、模型路由及 /api/bps-images/，不能把专属入口又送回主站。

在面板确认上报地址、保存、检查连接后，启用接收新绑定并创建地区规则。例如 US → nerd-us-1。一个地区可关联多个 Pod，使用 API Key 标识的稳定散列排序选择健康实例。心跳和入口签名健康探测都通过才接收新绑定。

## 地区识别

复用现有前端 IP 地区分析所用的 GeoJS 接口及 country_code 口径。浏览器 localStorage 不作为后端可信路由输入；服务端对经受信代理链解析的客户端 IP 查询 GeoJS，结果存 Redis 24 小时，失败短缓存 1 分钟。无需导入国家 IP 网段。私有/无效 IP 不向外查询，未知地区回默认主站。

首次建立绑定且 IP 缓存未命中时，可能发生一次最多 1.5 秒的查询；其他 Key 或入口实例也复用该 IP 的 Redis 国家缓存，不逐请求查询地区服务。每实例最多 8 个并行唯一 IP 查询，同 IP 合并请求。开启功能后，首次公共客户端 IP 查询会从服务器发送给现有 GeoJS 提供者。IP 归属不保证实际物理位置。配置 server.trusted_proxies，地区选择不信任客户端直接提交的国家头。

## 绑定与失联策略

在同一面板配置以下选项，无需另外部署地区识别器或购买地域 DNS：

新增设置在“网关服务”页签、Serverless 面板标题和绑定范围旁共用同一新功能提示；关闭任一提示会按当前管理员保存到当前浏览器，其他公告不受影响。

| 字段 | 默认 | 行为 |
| --- | --- | --- |
| `affinity_scope` | `api_key`（省略时相同） | 同 Key 固定一个实例；`api_key_ip` 则按 Key 和经过可信代理解析的客户端 IP 分别绑定，同 Key 可在 CN 和其他国家选择不同节点 |
| `fallback_to_primary` | `false` | 已绑定实例失联、重启或签名探测失败时保留绑定并返回 503；开启后只在业务请求转发前将该绑定原子改到主站 |

例如主站在海外机房、另一个 gateway 为 CN 请求提供出口，配置一条 `CN → cn-gateway` 规则，选择 `api_key_ip`。未知地区和未配置国家使用主站。Redis 国家缓存仍为 24 小时，识别失败为 1 分钟；绑定最后使用后保留 24 小时。原始客户端 IP 不写入绑定 Key，使用集群密钥 HMAC；IPv4 与其 IPv4-mapped IPv6 形式共用绑定，无效 IP 使用未知范围并走主站。

`api_key_ip` 适合多个地区共用同 Key、允许节点变化的请求。用户 IP 改变也可能换节点，不适合依赖节点内 BPS/WS 状态的跨请求会话。切换绑定范围使用独立 Redis 命名空间，已有 TCP/WS 连接不迁移；启用前先排空会话。回退后主站绑定会继续保持，节点恢复不自动切回。并发回退采用比较旧绑定后更新，不覆盖其他请求建立的新绑定。

回退只处理转发前的不可用判断；一旦业务请求发出、目标返回错误、SSE 已开始或 WS 已建立，都不向主站重放。Redis/注册表读取失败依然返回错误，不绕过绑定一致性和防重放保护。图片能力链接仍按原实例归属处理，不迁移文件或恢复丢失链接。

所有访问者仍先连接主站，再转发命中地区的请求；这种应用路由不会改善到主站的首段网络。管理、支付、异步任务和不在支持范围的协议仍留主站。

## 请求与会话边界

- 覆盖 /v1 及 OpenAI/Codex 根路径别名中的同步 responses、messages、chat/completions，以及 Responses WebSocket；图片生成、异步任务、管理、支付和其他协议端点保持原路径。
- 入口在现有 API Key 鉴权后路由，不申请第二份账号并发、不写第二份用量；目标继续正常鉴权、账号选择、计费。
- 默认同一 API Key 固定 Pod/启动实例，最后使用后保留 24 小时，不按单次地区变化重新分配；选择 `api_key_ip` 后每个 Key/IP 组合独立绑定。首次启用前结束已有 BPS/WS 会话，不迁移节点内会话状态。
- 默认主站也是绑定。未知地区/健康失败的新绑定回主站，之后不会因地区查询恢复就迁移已有绑定。
- 停用全局开关或 Pod 停止新绑定，已有绑定继续；删除 Pod 规则、实例重启或绑定目标失联默认返回 503，开启 `fallback_to_primary` 时可在转发前回主站。移除前先排空。密钥轮换会改变签名及绑定命名空间，需要协调排空。
- 跨节点转发包含绑定到方法、路径、认证头、客户端 IP、实例及时间的 HMAC，Redis 防重放；目标不再次转发。用户 Token 只发到管理员确认且通过签名探测的地址。
- SSE 即时刷新，取消传到目标；WebSocket 保持双向连接。转发失败不跨节点重试已发送请求。
- BPS 图片链接携带签名实例归属，匿名能力下载回到原生成 Pod；实例丢失时链接不可恢复。

统计为 UTC 当日已完成入口 HTTP/WS 请求、HTTP 错误及路由原因，保留 8 天；流内业务错误不一定改变 HTTP 状态。统计失败不改变计费或请求结果。Pod 表保留最近 24 小时注册，35 秒未更新视作未就绪。

## 转发等待预算

进程配置 `runtime.serverless_response_header_timeout`（环境变量 `RUNTIME_SERVERLESS_RESPONSE_HEADER_TIMEOUT`）控制请求写完后等待 Pod 响应头的秒数，范围为 `0..86400`，修改后重启转发请求的入口进程生效。默认 `0` 表示转发层不额外设置响应头截止时间，继续受请求 context、客户端取消和 Pod 自身上游超时约束。旧配置省略该字段时同样使用 `0`，允许 Pod 在上游排队或换号期间超过原来的 60 秒首响应等待。

正数会给业务转发设置有限响应头预算，应覆盖 Pod 的上游等待及换号总预算；它不限制响应头之后的 SSE 或 WS 连接时长。Pod 健康探测保留独立的 3 秒总预算，不受该业务值影响。流处理中的 SSE 保活在收到上游响应头后才启动，不能用于延长等待上游响应头的时间。

默认不设置额外截止时间时，异常 Pod 的未响应请求可能持续占用连接，直到请求取消或 Pod 的上游预算结束。需要限制这类占用时可显式设置正数；超时仍返回转发失败，已发送请求不会跨节点重放。本项只影响进程内转发，不修改绑定、计费、数据库或管理面板设置。回滚到旧二进制会忽略此字段，并恢复原有固定 60 秒转发响应头上限。

转发携带入口生成或校验后的 `X-Request-ID`，便于关联 Pod 日志。首响应前的传输失败记录为 `serverless.forward_failed`，包含 Pod ID、固定错误类别、耗时及配置预算；不记录原始 transport error、目标地址、请求正文或认证头。该事件描述主站到 Pod 的传输失败，不能直接解释供应商内部原因。

## 验证与上线

无数据库迁移，配置存现有 settings，注册/绑定/计数使用独立 Redis 前缀。代码完成不代表已启用，所有入口实例和目标 Pod 必须先部署兼容版本。先验证健康、可信 IP、协议回放和成本缓存，再由管理员显式开启；健康探测不调用模型。

旧配置不需要修改，仍按 Key 绑定且失联返回错误。旧二进制忽略两个新字段，并恢复按 Key 的旧命名空间和失联行为；回滚前先在兼容版本恢复默认配置并排空会话，不把混合版本集群当作已支持 IP 范围分流。

回归使用虚构 IP、miniredis、HTTP/SSE/WS 模拟服务，覆盖签名、防重放、重复 Pod ID、实例重启、断流取消、图片所有者与配置停用。模拟测试不等同生产流量验收。
