# 分组防蒸馏保护

入口：管理员 → 分组管理 → 编辑 OpenAI 分组 → RPM 下方的“OpenAI 防蒸馏保护（零缓存规则）”。新建分组默认关闭；先创建，再进入编辑单独保存。其他平台没有此设置，也不增加账号级或客户级开关。

## 设置与触发

- 保护默认关闭；开启后可设置暂停时长，范围 1–1440 分钟，默认 5 分钟。本项有独立的保存按钮，最多 10 秒生效，修改它无需保存整份分组配置。
- 按客户用户归并其 API Key，跨已开启保护的 OpenAI 分组统计最近 20 条有效请求；完整成功且上游明确提供缓存读取数的文本请求才计入。满 20 条且至少 18 条缓存读取为 0 时触发。未知缓存统计不当作 0。
- 媒体样本同时检查请求的图片、音频和视频内容及响应计量；上游未返回媒体 token 明细时，也不会把已知媒体请求当作纯文本样本。HTTP 协议转换与 WebSocket 每轮请求使用相同规则，不保存请求正文到保护状态。
- 请求通过 `previous_response_id`、`conversation`、`conversation_id` 或 `thread_id` 引用未展开的上游历史时，无法确认历史是否含媒体，按未知样本排除；不额外获取或保存历史内容。仅含完整文本历史的请求继续正常采样；普通会话标识和缓存键本身不属于历史引用。
- 暂停只限制该客户在已开启保护分组的新请求；未开启分组仍按原规则处理。不会自动改用更高价格的分组，也不会修改客户的账号状态。
- 由触发保护的分组决定暂停时长；暂停已经开始后不会续期，现有流式响应继续完成。期满后清空旧窗口重新采样，暂停前已开始的请求在完成后不补进新窗口。有效样本窗口闲置 24 小时后过期。关闭某分组保护后，该分组在配置生效时恢复放行。
- 触发后异步向客户账号邮箱发送通知，说明暂停及恢复时间。邮件失败不会撤销已经生效的保护。

零缓存只是保护信号，不代表已认定客户正在蒸馏。新会话、输入不满足缓存条件等正常工作负载也可能触发，开启前应结合分组服务用途判断。

## 运行边界

保护依赖已完成请求的缓存统计，无法撤回已经转发的首批高并发请求。需要限制突发量时，结合现有分组 RPM 和并发配置使用。

Redis 状态服务异常时按放行策略处理，避免因保护状态不可用而误暂停客户；此时保护能力暂时不可用，应通过服务日志排查。未知缓存统计较多的通道不会因此被判为零缓存。邮箱通知依赖已配置的邮件服务；采用最多 8 个并发的异步投递，没有持久化邮件队列，邮件未配置、投递繁忙、SMTP 失败或进程退出都可能导致通知失败，暂停仍生效。

管理员“新功能”标签的公告 ID 为 `group-openai-anti-distillation-initial-announcement`，创建提示与编辑设置共用该 ID。关闭记录仅保存在当前浏览器、当前管理员的 localStorage，沿用现有机制。
