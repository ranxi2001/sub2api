# 不含免费加速加价的文本采购估算

兼容上游的采购报价若已包含 Fast/UltraFast，可以在该账号的管理 API 中显式设置：

```json
{"extra":{"token_procurement_basis":"standard_tier"}}
```

沿用已有 `cost_multiplier`，例如普通基价的 0.25 倍。批量接口 `/api/v1/admin/accounts/bulk-update` 应同时指定明确的 `account_ids`。这是 API-only 选项，账号编辑器会保留它；不是客户售价开关。保存后应回读账号，并使用利润运维 `basis=account_usage` 的固定窗口刷新报表。

对于带有效 `customer_cost_details.free_fast` 或 `free_ultrafast` 的文本用量，使用冻结的 `customer_cost_details.total_cost` 作为普通档位基数，乘该请求保存的采购倍率。提交过的响应头超时附加次数按冻结的客户报价倍率与请求倍率之比保留，必须为有效整数；不从客户实扣金额反推。普通档位记录保留原基数。历史已记录的快照不改写；选择该口径时，历史估算可以使用它自己的普通价证据重新计算。

有加速档位但没有普通价快照的历史记录，成本保持未知并计入未覆盖请求。不会猜测除以 3、6 或 8，也不会从客户实扣金额反推采购价。图片、按次、视频、gateway 与已对账的供应商采购金额不受该文本估算开关影响。

`account_stats` 与 `standard_charge` 的旧语义不变。后者的 `total_cost` 仍可能包含实际加速档位，不能当作去掉免费加速加价的开关。未配置账号保留原行为。

新增普通价投影列和函数采用追加迁移。后台继续按五分钟切片重建旧聚合；旧 worker 写出的未投影切片在受限查询窗口内从事件补算。不会重写用量、客户扣费或原采购快照。回退二进制前应清除新配置并评估新快照的兼容性：旧版无法识别 `standard_tier` 快照，会把其采购成本显示为未知。回退二进制不会撤销数据库迁移。

这里只是采购估算，不能代替供应商实扣凭证。修改前应确认上游报价基数；多站共享钱包不可重复计算同一笔上游消耗。

账号列表显示今日和累计采购成本，账号统计弹窗显示所选日期范围的采购成本。金额与利润运维共用采购估算规则，存在待核实记录时会同时显示已知成本笔数和总笔数；全部待核实显示「—」。原账号计费字段继续用于额度与调度判断。
