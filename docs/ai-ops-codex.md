# AI 运维：Codex SDK 诊断与受控执行

入口：管理员「智能运维 → AI 运维」。设计：[Issue #662](https://github.com/ranxi2001/sub2api/issues/662)。Node/Codex 诊断服务属于运维仓库，策略、权威检查、执行、预算和补偿属于应用后端。

默认只读且控制面关闭。部署辅助服务后可查看诊断与建议；只有部署显式启用控制能力、管理员保存非关闭策略并解除急停，才可执行生产参数/独立暂停变更。模型及辅助服务均不持有生产写密钥。

## 配套与部署开关

应用服务配置：

```dotenv
SUB2API_AI_OPS_URL=http://127.0.0.1:17862
SUB2API_AI_OPS_TOKEN=<与辅助服务AI_OPS_TOKEN一致的独立随机Token，至少32字节>
# 独立的部署授权，默认关闭；开启不等于策略已授权执行。
SUB2API_AI_OPS_CONTROL_ENABLED=false
```

辅助服务在运维仓库 `operations/src/ai-ops/`，环境、systemd、隔离要求和异常进程锁恢复见该仓库 `operations/deploy/sub2api-ai-ops.README.md`。配套 PR 为 `ranxi2001/sub2api-operate#7`，协议从 `4fcd939169c6ff21d959a11300fddb17fc916e57` 的实现继续追加，部署应固定实际评审的 head。

应用代理只接受 loopback 字面地址 `127.0.0.1` / `::1`，不接受 URL 凭据、路径、query、fragment或重定向；远端管理机通过受控隧道映射loopback，不公开端口。Token只存服务端，禁止填前端。配置错误返回不可用，不静默降级。

控制循环只在明确授权的 full 实例运行，每分钟执行有界核对；PostgreSQL串行事务与全局锁限制跨实例重复动作。gateway、纯本地区域快照以及已启用 Serverless 路由的控制场景会拒绝启用生产变更：尚不能证明所有节点具备及时且一致的权威限制时，诊断仍可用。生产部署前须验证所有接流实例版本，不把共享缓存成功当作全部地域已生效。

## 诊断与证据

日常使用从页面上方的「运行诊断」开始：确认固定分组和时间窗，勾选本次模型费用确认，再开始一次诊断。运行中会刷新所选任务，完成后先展示结论、建议和发现；分析限制与缺失证据有醒目提示，任务 ID、完整时间窗和采集 JSON 收在「任务与采集详情」。历史记录与运行限制默认折叠。

冷却期按已知的上次开始时间显示倒计时并禁用开始按钮，最终限制由服务端决定。每次提交后都需重新确认模型费用；提交结果未知时，先成功刷新状态和历史再决定是否重试，不自动重新提交。每日上限包含失败任务，按 UTC 日期计数；当前接口没有返回已用/剩余次数，保留历史条数不能代替剩余额度。429 只能确认间隔或每日次数受限，页面不推断已经耗尽当日额度。

生产执行在报告下方的高级区域，默认折叠；折叠不卸载审批和探针组件、不清空进行中的状态，也不保存策略或发起操作。执行明确关闭时只展示简短只读说明；执行启用或状态尚不明确时，全局急停仍在折叠外。中英文界面采用相同交互，沿用原 AI 运维新功能提示 ID。

诊断页显示固定分组、时间窗、自动调查间隔、历史、证据年龄和 `ok` / `unavailable` / `truncated`。手动创建须确认可能的模型费用；辅助服务预算同时约束手动与定时调查。页面刷新不创建任务，轮询有时长上限，离开页面不取消已开始的模型请求。结果不确定时先刷新历史，不自动重试创建。

只发送白名单数值、枚举、匿名ID与聚合，账号身份、凭据、任意extra、用户正文和原始错误正文不进入模型。最终请求失败与上游尝试失败分开；成功证据必须具有完整trace/terminal。缺数据、低缓存、任务难度、裸首字或单条5xx均不足以授权生产操作。

## 策略与显式授权

策略包含 `disabled`、`approve_each`、`bounded_auto` 三种模式，以及独立急停。保存使用revision条件更新；旧页面、旧提案、旧worker不能覆盖新策略。管理员配置固定单组、账号白名单、共享上游容量域、最少健康候选/并发底线、参数范围、步长、每日动作次数、冷却、观察时间、证据年龄、样本和错误率阈值。

当前执行范围保守限定为有明确新鲜短窗/周窗额度的OpenAI主OAuth账号，且只属于策略的一个分组。共享其他组、影子账号、未知容量域、不同模型/协议覆盖、额度未知，以及质量/准入/性能/定时开关等其他控制器托管时拒绝变更。相同凭据身份不能通过填写不同容量域冒充独立备用。未知在途量显示为未知，不伪造为0。

并发必须为正整数；`concurrency<=0` 在原系统表示无限制，不能用来停号。负载因子只影响对应调度路径的软偏好，不能当硬限流；实际调度模式及参数传播仍需核验。自动授权仅包含安全条件满足时的降并发、独立暂停和使用已授权成功探针的恢复；负载因子和扩并发由人工逐项批准。

## 冻结、批准与执行

1. 从已完成诊断选择建议，后端按 `run_id/proposal_index` 自行读取原始候选；浏览器不能替换账号、值、scope或证据。
2. 后端重新采集数据库权威证据，冻结 before/after、账号和策略revision、作用组、有效期与摘要。条件不足返回明确blocked原因，不提供执行入口。
3. 管理员核对差异与影响，确认准确摘要后执行。条件更新、动作账本、独立AI状态和outbox在同一事务提交；同一提案最多对应一个动作，丢响应后按原ID核对，不换ID重试。
4. 账号的手工schedulable、质量隔离、额度及冷却不被清除，定时任务不因AI暂停取消。人工或其他控制器改变配置后，旧动作/补偿返回冲突。

全局一次只允许一个传播/观察中的动作；检查全策略范围当前备用容量，并将同容量域视为相关风险。缩容不杀已有请求；槽位准入及OpenAI实际发送前重新检查AI暂停。已发送的生成不重放、不清response owner绑定。

## 恢复探针

AI暂停不会随重启、模型失联或时限到期自动解除。普通usage完成时间可能属于暂停前的在飞请求，不能作为恢复依据。页面提供独立费用确认的一次性恢复探针：仅对当前AI拥有的暂停，使用原暂停冻结的模型、effort和受支持native HTTP协议，固定短提示和输出预算；不能用健康模型B恢复故障模型A。

探针先持久预留额度与权属，再发一次请求，不自动重试。完整结束并回答准确 `OK` 才记passed；超时、崩溃、未知状态不记成功。默认最多每天 `min(3, daily_action_limit)` 次、受账号冷却限制。通过只生成证据，不直接清暂停；新鲜通过证据才可进入人工恢复或已授权的自动恢复，其他硬限制继续生效。不支持的WS恢复路径明确拒绝。

## 观察、回滚和急停

动作记录区分传播中、观察中、成功、未知、冲突、失败和已回滚。参数在共享调度快照确认后才开始观察；无缓存/传播不明或样本不足显示inconclusive。按同条件完整请求比较变更前后错误率；劣化时执行原动作预授权的条件补偿。

回滚检查当前owner、revision及新鲜证据，缩容/重新暂停也重新检查剩余容量，禁止恢复整个旧账号对象。条件不足时保留当前安全限制、急停并展示原因，不盲目回滚。重新暂停的补偿保留可追溯所有权，后续仍可探针恢复。

急停立刻使旧策略revision失效并阻止新动作；既有结果核对和安全补偿仍运行。卸载诊断服务不会删除应用内动作记录或自动解除暂停。停止/回退不认识AI暂停的旧二进制前，先建立等价保护或排流；单纯回退二进制不能代替安全状态处理。

## 存储、权限与兼容

- 迁移333新增策略、提案、动作、暂停所有权和探针记录，以及账号配置revision触发器；用量/额度/票据等观测更新不应无故令配置revision失效。
- 生产操作仅full管理员，观察员、普通用户和受限管理密钥无权批准、执行、探针或回滚。Node采集身份仍只有读取权限。
- 控制API位于 `/api/v1/admin/ops/ai/`：`policy`、`halt`、`proposals/preview`、`proposals/:id/apply`、`actions`、`actions/:id/rollback`、`probes`；写接口拒绝未知字段，不接受通用URL/指令/SQL。
- 模型推理、真实探针、数据库及控制器的资源成本分别有预算；次数上限不能承诺供应商账单金额硬上限。
- 新功能提示共用 `ai-ops-codex-observe-initial-announcement`，不会因追加控制能力反复重置已关闭提示。

### 传播超时与可比较的效果证据

配置传播超时会急停策略并使旧提案失效。动作保留 `propagation_pending` 和容量占用；即使管理员解除急停，也不能绕过未解决的动作继续调整。后台继续核对，只有确认传播、完成条件回滚或发现人工接管后才转移状态。旧版本留下的 `inconclusive / propagation_unconfirmed` 同样占用容量并继续核对。传播确认不会自动解除急停；确认后重新开始完整观察窗口。

冻结证据同时记录模型、effort、协议、输入长度桶、缓存桶及输出长度桶。批准执行及效果比较要求前后这些条件一致；观察窗口不得包含传播确认前的请求。不同分桶、样本不足，或旧记录缺少分桶/传播确认时间，均显示效果未知，不能据此宣称成功或触发自动回滚。旧的未执行提案需重新预览；本次只扩充已有 JSON 数据，不增加数据库迁移。

当前比较仍是账号错误率检查，尚未实现 Issue #662 要求的全局 SLO、对照流量和 TTFT/TPS 联合验收；跨实例执行覆盖、实际隔离与真实模型验证也仍待完成。此处的保护不能作为开放自动执行的完整验收结论。
