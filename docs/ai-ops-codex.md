# AI 运维：Codex SDK 只读诊断（M0）

入口：管理员「智能运维 → AI 运维」。关联设计 [#662](https://github.com/ranxi2001/sub2api/issues/662)。

本阶段复用现有监控和账号 API，展示指定分组的证据、诊断、调参及隔离建议。建议不会执行：没有批准、应用、账号开关或参数写入接口。该功能默认关闭；未配置辅助服务时，状态接口返回关闭、历史为空，不启动模型调用。

## 配套服务

Node 辅助服务位于独立运维仓库的 `operations/src/ai-ops/`，负责固定 API 的只读采集、白名单投影、Codex SDK 隔离运行和有界记录持久化。应用后端只代理四个固定接口，不透传用户指令、scope、URL、管理凭据或任意请求体。

本阶段配套协议对应运维仓库提交 `292c7bb0939976ef299f786e40b7f08d61004f21`；先在隔离环境联合验收，再按维护流程部署。单独升级应用不会自动安装或启动辅助服务。

管理面与辅助服务通过仅 loopback 的 HTTP 连接；应用进程添加：

```dotenv
SUB2API_AI_OPS_URL=http://127.0.0.1:17862
SUB2API_AI_OPS_TOKEN=<独立生成的至少32字节随机Token>
```

Token 应与辅助服务的 `AI_OPS_TOKEN` 一致，由服务端环境/密钥系统注入，不填入前端。仅接受 `127.0.0.1` 或 `::1` 字面地址，禁止凭据 URL、路径、query、fragment 及重定向；放在独立管理机的服务应通过受控隧道映射到 loopback，不公开监听端口。服务端配置变更后按既有维护流程加载，不在页面自动重启服务。

删除以上配置可关闭接入，不删除独立保存的历史诊断。仅配置一项或配置错误时返回不可用，不静默降级到其他地址。

## 页面行为

1. 查看运行模式、固定分组、时间窗、自动诊断间隔、任务状态和保留的历史记录。自动诊断默认关闭，由辅助服务部署配置控制；开启后会持续消耗模型额度。
2. 确认可能产生模型调用费用后，手工发起一次诊断。重复提交、冷却时间和每日请求上限由辅助服务强制限制。
3. 查看已采集证据及其 `ok` / `unavailable` / `truncated` 标记、模型诊断、证据引用和未执行建议。
4. 自动刷新有时长上限；停止刷新和离开页面不会取消已经开始的模型调用。提交结果未知时先刷新历史，不自动重试创建。

观察员、受限管理密钥和普通用户均无访问权限。人工管理员仍须核查建议，不能以模型结论代替真实容量、额度、质量隔离或业务请求完成状态。

## 数据和故障边界

- 只采集配置分组、限定时间及分页预算内的数据；原始账号响应、凭据、备注、用户正文、IP、错误正文不会送入模型。
- 快照是受限观测，可能缺失或截断。单个错误或缓存率不能独立证明账号故障；没有共享容量域、按模型/effort分桶等证据时，报告应明确限制。
- 运行中进程退出，重启后标记为 interrupted，不自动重放调查。每日预算独立于历史保留，删除旧记录不会补回额度。
- Codex SDK 的线程和沙箱不是生产操作的幂等或权限边界。M0 只保存建议；后续写能力必须另补 CAS、所有权、容量预算、审批和补偿。
- 远端 HTTP 错误正文不回传浏览器，接口只给通用错误；诊断失败不会修改账号、调度、Redis、计费或现有请求。

本功能使用 `ai-ops-codex-observe-initial-announcement` 提示 ID，侧栏、智能运维导航和页标题共用。关闭行为沿用当前管理员在当前浏览器的 NewFeatureBadge 机制。

## 验证状态

实现包含 Go 管理面权限/代理边界和 Vue 页面交互回归；辅助服务包含离线采集投影、预算、崩溃恢复与 SDK 隔离回归。按仓库约定由 CI 执行，未在本地启动测试、构建、浏览器截图、真实模型调用或生产验收。源码合入不表示辅助服务已部署或功能已启用。
