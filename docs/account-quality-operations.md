# 降智运维

管理员侧边栏「质量运维」集中管理账户质量检测。每个账户可同时配置一条分组/调度规则和一条自动 BPS 规则，暂停只占用同类规则名额。可批量选择账户创建，也可多选已有规则批量编辑；单条规则仍可编辑、暂停、手动触发或删除。

## 降智后复测静置

分组/调度规则中的「降智后复测静置时间」按分钟设置，范围为 0–10080，默认 0 沿用原检测计划。单账号规则、动态分组规则、检测模板和复制共用此配置；批量编辑时归入「处置动作」，未勾选该项的规则保留各自设置。观察规则不使用静置，自动 BPS 规则沿用独立的恢复间隔。

一次完成的检测确认降智、且本规则实际持有分组移除、调度关闭或模型隔离后，开始静置本规则的全部检测模型。静置期内不运行该规则的定时检测、立即执行或 5xx 触发；其他规则和正常模型的业务流量不因静置本身改变。截止时间持久化到规则状态，重启与其他节点不能绕过；新的明确失败会开始新的静置，超时、传输失败和无法判断不会延长静置。

静置截止只允许再次检测，不会自动放行账号或模型。后续通过且开启自动恢复时，仍由原有所有权与恢复条件决定是否恢复。关闭自动恢复时只记录通过。静置不能保证账号恢复质量，也不能据此认定检测频率是降智原因。

已隔离规则新增或修改静置时长，从下次确认失败开始采用新值；已经开始的静置保留原截止时间，设为 0 可停用本规则的静置检查。没有数据库迁移；回退旧二进制会忽略新增静置字段，原有质量隔离仍由原恢复规则管理。

## 多选编辑与窗口适配

- 账号规则卡片左侧复选框用于批量选择，点击账号名称仍用于筛选运营记录。搜索后可全选当前结果，切换搜索条件保留此前选择；清空已选会取消所有勾选。
- 点击「批量编辑」，勾选需要统一修改的检测模型、检测频率、检测配置、失败处理与目标分组、自动恢复或定时检测开关。未勾选的字段保留每条规则自己的值。初始输入来自第一条已选规则，检测配置包含检测方式、题目、参考答案、推理强度、检测次数和判题模型。
- 保存前刷新规则列表，合并每条规则的配置。逐条保存时显示处理进度；部分失败会保留失败项及错误信息，重试只处理剩余规则。此流程不是服务端原子批量事务。
- 桌面双栏使用可用宽度和剩余窗口高度，两个列表分别滚动；矮窗口收紧顶部区域。窄屏上下排列面板，手机端运营记录按卡片展示，编辑抽屉的保存按钮固定在底部。

## 配置

- 配置测试模型、题目、参考答案、推理强度、五段 Cron 和每轮 1–8 次测试。判题默认选择普通分组和模型，也可明确选择复用安全审计 Jev；两者均填写判题提示词。Jev 的启用条件、原生协议、独立耗时与错误处理见 [Jev 判题说明](quality-jev-judge.md)。
- 检测模型下方提供 `gpt-6-astra`、`gpt-6.1-sol`、`gpt-5.6-sol` 快捷标签，点击即可添加，已选模型不会重复添加，并优先填入空白模型行；门票探针保持单模型，点击其他标签会替换当前模型。
- 展开「新增自定义标签」，可用换行、空格、逗号或分号一次保存多个名称。标签按管理员保存在当前浏览器，后续新建、编辑及批量编辑规则均可复用，不跨浏览器或设备同步。保存标签不会自动修改检测模型；删除自定义标签也不移除已选模型。内置标签不可删除。
- 糖果题沿用账号的答题传输，不限于 OAuth 账号，API Key、Setup Token 等现有传输支持的账号类型也可使用。按账号路由检测时，显式配置的模型映射（含别名和通配符）可作为检测模型，即使上游 `/models` 未列出；未被映射覆盖的模型先读取目录，读取失败明确提示目录不可用；读取成功但未列出时，原生回答检测允许手动选择现有账号策略许可的名称。可配置不保证上游实际可用，明确的运行时模型拒绝仍会使该模型跳过检测。状态探针、BPS 通道和自动透传仍要求各自目录确认，缺失时提示未知而非确定不支持。账号映射白名单、已知厂商/退役模型限制及明确拒绝记录继续生效；401、权限失败和无可用路由不会作为模型能力结论。
- 内置糖果题及预期答案 `21` 沿用 frontier PR #1 的约定；可改为自己的题目和答案。此检测是单题质量门槛，不是完整模型能力评估。预期答案只属于题目配置，判题模型不固定为 Luna。
- 由配置的模型比较回答与参考答案的语义，例如 `21个。` 可以与 `21` 等价。判题分组自动选择支持该模型的可调度账户，排除被测账户并占用并发槽；请求或输出解析失败时最多尝试 3 个账户。只有明确的 `incorrect` 结论触发失败动作；超时、鉴权错误、未完成响应、无可用判题账户和 `unknown` 均不触发账户变更，也不会恢复账户。
- 失败动作二选一：取消指定分组的账户归属（其他分组不变），或关闭账户调度（分组不变）。
- 自动恢复默认关闭。开启后，后续一整轮全部通过才尝试恢复。后台按账户 ID 测试，移出分组或关闭调度不妨碍复测。
- 服务每分钟扫描到期计划；「立即检测」进入下一次扫描，不直接在浏览器中调用模型。

## 随机推理题

在检测方式中选择「随机推理题」。保留测试模型、判题分组、判题模型与判题提示词，题目和参考答案由服务端在共享批次中生成，无需手工填写。旧规则和糖果题不会自动切换。

- 包含路径计数与加权异或两个题族，运行时随机生成参数。每模型测试次数可设为 1–8；同批账号和模型按样本序号共享同一组题，两个题族交替。不同规则配置的测试次数可以不同，共同序号仍使用相同题目。
- 参考答案在本地由有界动态规划或穷举求出，不调用被测模型求答案，不向被测模型发送参考答案。题目生成失败时记录为无法判定，不发送测试请求，不触发失败动作。
- 判题沿用配置的分组和模型，选择支持模型的可用账号并排除被测账号；只发送参考答案和候选答案两个值，不发送题面。只有明确 `incorrect` 才触发失败动作。未配置判题器、请求失败、解析失败或 `unknown` 均不触发失败处置或自动恢复；多模型轮次同样遵守此边界。

以上分组选号和仅发送两个值的说明适用于默认普通 LLM。显式选择 Jev 时复用安全审计配置，题面、参考答案与候选回答作为三个独立 state 数据字段，遵循 [Jev 专用协议与安全门](quality-jev-judge.md)，不经过普通分组选号。
- 每个实际题面、参考答案、题目标识、题族和生成器版本保存在管理员检测结果中，便于复核；可在运营记录详情展开本次题目。可复用规则和分组模板不保存生成实例，重启后下一轮继续生成新题。
- 使用 BPS 通道时仍只观察、不处置；5xx触发已选随机题规则时保留该题型及外部判题器，不回退固定糖果题。原有上游5xx保护与冷却机制不变。
- 开源的是生成器与本地求解程序，不发布运营使用的固定题库、实际题目/答案清单或私有测试记录。新版本可更新生成器与题族；不需要公共解密密码或密钥分发，生成器版本记录用于追溯。

随机参数减少固定题目与固定答案的硬编码适配，但上游仍能看到请求题面，公开生成规则也可被识别，不能保证抵御全部提示词注入或识别真实模型。两个题族不是完整能力评测；不同参数的区分度仍需实测，不能保证某个模型永远答错。不要仅凭一次失误认定账号降智。

### 同时同题与处置基线

共享批次按服务器 UTC 分钟标识，参与的是原本到期或已经获准触发检测的账号，不额外扫描全池。数据库首次创建批次后固定题目、参考答案和生成器版本，其他后台实例读取这份题目。每批有两分钟的请求启动窗口，收集截止为批次开始后十二分钟；账号/模型并发上限、原有十分钟答题时限和重试预算继续生效。排队、模型目录读取或重试导致启动窗口关闭时，不再发送新的答题请求，明确记录无法检测。

每份答案先保存为“等待同题对照”。启动窗口关闭，且所有已加入的账号完成收集后，后台统一比较；未完成的账号最多等待到批次收集截止。等待比较不占用答题 worker。批次进度与已收集结果在数据库中持久化；后台重启后继续比较，不重发已收集的模型请求。收集事务尚未完成就崩溃的请求无法声称已经完成，按原租约和批次期限保守退出。

比较条件包括同批、同题、生成器版本、模型原名与当次账号映射目标、思考强度、配置通道、所选答题路径和完整判题配置。BPS、普通账号路径、SIWC、Prism 及合成测试分别比较。这里记录的是本站选择的路径和模型映射，不是上游模型身份认证；供应商内部路由、共享凭据或共同上游仍可能影响结果。

| 原始结果与对照 | 历史记录 | 质量处置依据 |
| --- | --- | --- |
| 明确答错，且另一个账号同条件通过 | 保留答错及对照数 | 可进入原有模型隔离、移组或关闭调度策略 |
| 全部答错，或没有有效通过账号 | 保留答错，显示“同题缺少通过对照” | 不新增质量限制，不凭失败恢复已有隔离 |
| 请求失败、判题未知、模型跳过、超出时间窗口 | 保留原始状态及比较原因 | 不作为通过基线或降智依据 |
| 本题明确通过且时间窗口有效 | 保留通过结果 | 按原有自动恢复与所有权校验处理 |

对照按其他账号 ID 去重，同一账号的重复规则或模型别名不能为自己提供通过基线。暂停、编辑或已失效 5xx 轮次不能充当有效通过对照。处置事务再次检查原规则版本、租约、5xx episode 和当次模型映射；收集过程中修改了目标映射时只记过期结果。账号处置、历史动作更新和批次完成标记在同一事务内提交，重复扫描不重复执行。旧的质量隔离和原生 429/5xx 保护不会因新策略自动解除。随机题的 5xx 事件检测继续记录；只有持久 episode 保护的模型冷却规则可以在延后比较后处置，依赖瞬时队列的旧事件规则保守记录，避免旧信号恢复账号。

优先调度、账号性能监控及渠道运维采用相同口径：尚未完成对照、没有通过基线或超出窗口的随机题结果，不计为可处罚的降智样本。旧随机题历史保留，并显示“无跨账号同题对照”；不从当前数据倒推旧题难度，也不补写对照证据。

迁移 `326_quality_shared_batches.sql` 新增运行时批次与收集进度表，保留七天；不保存账号凭据，不增加真实模型请求。结果详情展示批次、窗口、其他账号的通过/答错/不确定计数及处置依据，不导出其他账号身份。规则、模板及导入配置不能伪造这些结果字段。所有承担检测任务的主实例升级后才具备完整保障；回退旧二进制前应暂停随机题规则，旧程序会恢复原来的独立出题与处置行为。

旧二进制不识别 `random_reasoning` 时，降级前同样需要暂停或改回旧题型。混合版本运行时不能保证全部检测都使用共享对照。

## 恢复与并发

数据库租约防止同一账户的智力检测计划同时执行。执行完毕重新校验计划版本、启用状态、租约，暂停或编辑期间产生的旧结果只记历史，不修改账户。

恢复只撤销该规则真正执行的变更，不开启原本已关闭调度的账户，不新增原本不存在的分组归属。分组恢复保留优先级和分组模型限制。恢复检查对应动作真正拥有的字段：账户非 active、原分组已删除或待恢复成员关系已存在时拒绝分组恢复；调度恢复检查账户状态与有效期。无关账号字段更新（包括 updated_at 变化）及其他分组变化不会单独阻止恢复。模型限制、并发与 BPS 恢复仍校验各自写入的快照。

手动改动后可能出现「恢复冲突」，应核对当轮证据与账户当前状态。新轮次在结果配置 JSON 的 quality_restore_diagnostic 保存具体触发项、动作范围及最小检查证据，不保存凭据、原始 Extra 或请求正文；旧历史未保存原因时仍明确显示未知，不用当前状态倒推历史原因。

若独立分组动作发现本规则曾移出的所有成员关系都已在场，页面显示「分组已在场，旧归属待对账」，raw quality_action 仍为 restore_conflict。系统不认领外部成员关系，不覆盖其优先级或模型限制，也不删除旧 ownership；部分归属已在场、原分组删除、模型限制不匹配或组合模型隔离动作仍需核对恢复。组合动作遇到冲突时整轮回滚，不能把分组已在场误报为模型恢复成功。该证据是当轮检查值，不是实时调度可用性证明。

保留旧 ownership 意味着：相同外部状态下，后续通过仍会重复冲突，后续失败也可能只记 already_quarantined；这条历史动作不能证明外部已加回的分组仍被隔离。缺少显式所有权对账能力时，重复答题不能重建隔离基线。请管理员核对后另行决定处置，本功能不会自动接管或清理这些记录。暂停规则本身不会恢复账户。模型隔离规则删除前必须按下述流程审查和恢复；其他动作删除仍不会自动恢复原分组、调度或 BPS。删除会清除该规则历史及恢复记录，不应作为诊断或无损对账手段。

账户变更、恢复记录和调度缓存 outbox 事件在同一数据库事务内提交，包含已移出分组以使旧分组的调度缓存也得到刷新。历史最多每计划 200 条，页面默认保留 100 条，按现有定时任务清理超过 7 天的记录。请求响应只作文本展示。

## BPS 与分组规则共存

迁移 `254_quality_bps_coexist.sql` 将每账户唯一限制调整为按处置类型分别唯一，不修改已有规则或检测记录。账号编辑页和质量运维的新建/批量选择均允许为已有分组/调度规则的账号添加 BPS 规则，反向也可以；同类规则仍需编辑已有规则。

两类规则独立保存检测频率、连续次数、恢复快照与记录，同账号检测仍串行执行。BPS 规则默认每 30 分钟通过正常协议探测，不经过 BPS。开启 BPS 不直接加回分组；分组规则开启自动恢复后，需自己的检测通过才恢复原分组。糖果题可通过 BPS 检测，状态探针始终检测正常协议。

已有两类规则的数据不能直接恢复旧的每账户唯一索引；回退该约束前需先处理重复账号规则。

## 按模型隔离，全部降智才移出分组

答题检测新增可选动作 `isolate_models`，旧规则不会自动切换。选择检测模型和目标分组，按需开启自动恢复；无需另填冷却模型名单。账号级状态探针不能使用此策略。

| 本轮模型结果 | 模型处置 | 所选分组 |
| --- | --- | --- |
| Sol 答错、Astra 通过 | 仅隔离 Sol | 保留 |
| Sol、Astra 均明确答错 | 分别隔离两个模型 | 移除本规则选定且原本存在的归属 |
| 全部隔离后，Astra 通过、Sol 仍答错或未知 | 自动恢复开启时仅恢复 Astra | 加回本规则移出的原分组 |
| 所有模型均通过 | 自动恢复开启时分别恢复 | 恢复本规则移出的原分组 |
| 含超时、判题未知、未检测或跳过 | 不新增对应模型隔离，也不解除其原有隔离 | 不因这些结果新增整组移除 |

“全部降智”要求本轮所有检测模型都有明确的失败结论，不使用跨轮次的旧结果补齐；账号内映射至同一上游模型的别名共用隔离，同轮答错或未知不会被另一个通过的别名解除。隔离针对该账号的所有分组，未参与检测的其他模型不受影响。恢复模型只撤销本规则持有的隔离，不清除原生 429 冷却、手工限制或其他运行状态；也不会打开原本关闭的账号调度。此策略不改变账号并发。

隔离保存在账号 `extra.quality_model_isolation`，与原生 `model_rate_limits` 分开，没有自动过期时间。重启、暂停、原生冷却清理均不会自行放行；关闭自动恢复时，通过仅记录结果。后台继续按账号 ID 直接复测，不受自身调度隔离或分组移除影响。

本策略和旧“仅冷却指定模型”共用模型结果归并、别名处理、隔离/恢复及历史动作生成函数；与旧“移出指定分组”共用分组变更和 outbox 事件函数。组合规则仅负责“何时调用这些能力”，不另外实现一套调度器。

模型、分组快照和缓存事件在同一事务提交，旧租约结果不能处置账号。至少一个模型明确通过且开启自动恢复时，恢复原有分组的优先级、创建时间及模型限制；不新增原本没有的归属。发现目标分组已删除、人工重建归属、隔离记录被其他操作替换或模型映射改变时停止自动恢复，整轮回滚并显示冲突。

持有本策略的隔离记录时，允许暂停、修改检测计划和切换自动恢复；修改动作、检测模型、目标分组或删除规则之前，必须先恢复本规则的处置，避免失去持久隔离的恢复依据。旧规则已经移出分组或关闭调度时，保存切换到本策略会自动恢复本规则的旧处置，并清理旧恢复记录，无需先复测通过，也不要求开启自动恢复。恢复和策略保存处于同一事务；账号状态异常、调度恢复时账号已过期、原分组已删除或分组归属被人工重建时，提示具体冲突并撤销本次全部修改。只恢复旧规则实际移除的分组及其优先级、创建时间和模型限制，不新增原本没有的分组归属，不改动并发、模型冷却或独立 BPS 规则。新策略从后续检测结果开始处置模型，不使用历史检测结果生成隔离。

无需数据库结构迁移。旧二进制不识别新隔离键和新动作，不能保证调度隔离；降级前须恢复全部此类规则的处置，并改回旧动作或删除规则。混合版本滚动部署期间也不能保证旧实例执行模型隔离，应在实例全部升级后启用新策略。

## 模型目录凭据错误

账号测试列表通过 `AccountTestService.FetchOpenAIAccountModels` 读取共用模型缓存，之后才投影账号映射。OAuth 目录来自 Codex manifest；API Key 来自账号 `/models`。缓存新鲜期 60 秒，旧快照最多保留 5 分钟，过期刷新失败可保留旧目录；目录未出现某个名称不是上游实际执行拒绝的证据。

模型列表返回上游 401 时，API 保持 502，业务原因 `OPENAI_CODEX_MODELS_CREDENTIALS_INVALID`，安全元数据仅含 `upstream_status=401` 和 `credential_state=rejected/revoked`。这表示被选账号的凭据问题，不使管理员登录失效，不证明封号或降智，也不返回 provider 正文。普通 OAuth 沿用既有凭据失效缓存/临时不可调度处理；明确 `token_revoked/token_invalidated` 走既有凭据错误状态，不能靠重试列表恢复。应在账号管理核对并按现有重新授权流程处理。模型列表路径本身不额外强制刷新普通 OAuth token；后台刷新沿用原 token provider/refresh service。Agent Identity 仅沿用原失效任务恢复后重取一次的机制，API Key 不用 OAuth 的账号故障转移规则。

凭据替换后，请求头参与缓存键计算，新的凭据不会复用旧凭据的目录缓存；失败结果不会写成成功目录。列表的本地兜底不能遮蔽明确的凭据错误。以上描述为源码调用链，不能据此判断某个真实账号当前状态。

## 删除模型隔离规则

1. 在规则删除确认框中，使用既有「隔离归属」预览核对每个模型、分组、当前所有者及变化字段。目录和原始账号数据不会替代 ownership 证据。
2. 无冲突且没有运行中任务时，管理员明确勾选确认，执行「暂停规则并恢复，再删除」。后端在事务锁中重建预览并核对 rule/account/state/lease 的 fence；版本变化必须重新预览，不能自动重试旧确认。仅恢复仍匹配本规则的隔离模型和原始分组成员快照，分组优先级、原模型限制一并还原，账号在线状态、调度开关和并发保持原值。
3. 恢复与暂停原子提交，并发中的旧任务不能重新施加隔离。页面重新预览后，管理员另行确认删除；DELETE携带新的fence，并在同一归属事务内再次核对版本及实时ownership。恢复与删除之间发生修改时返回409，保留规则并要求重新预览。恢复成功但删除失败时保留已暂停规则和错误项，重试仅删除剩余项；取消删除不会重新施加隔离。

外部模型所有者可以使用原有显式对账放弃旧快照，外部限制不变。仍标本规则但内容被改、已重建的组成员、已删除组、其他规则保存的组归属或无快照的孤儿标记都会保留并展示具体冲突；先在账号/分组页核对处理，再重新预览。不存在强制接管或覆盖选项。账号异常/过期时不恢复，也不会把账号改成在线。删除 API 继续保留 isolation guard，并检查本规则残存的实时模型 ownership，防止静默删除或遗留孤儿归属。

## 普通账号保存与隔离运行态

`extra.quality_model_isolation` 由质量运维服务管理。普通单账号保存（包括账单设置入口）在持有账号行锁后采用数据库最新隔离值；客户端旧快照、缺失或null不能覆盖或擦除新隔离，也不能复活已经通过专用恢复流程移除的隔离。普通批量保存及管理端Extra部分保存同样不接收该字段。

此保护不修写历史冲突，不清除ownership，也不放宽“同reason但时间不同即不相等”的guard。合法恢复仍使用既有归属预览、明确确认和事务版本复核；账号在线状态不由本修复改动。
