# 账号性能监控

账号性能监控按全局配置的滚动周期计算有效样本的 TPS、流式首 Token 耗时、完整质量检测轮次的降级比例及本进程上游 HTTP 错误率，默认使用最近 **60 分钟**。每项指标可分别设置低于和高于时暂停的阈值；百分比范围为 0–100。监控默认关闭，未设置的上下限不参与判断。

在「系统设置 → 网关服务 → 账号性能监控周期」填写统计周期，单位为分钟，范围为 1–1440 的整数，默认 **60 分钟**。所有账号的平均 TPS、首字平均值与探针轮次降智率共用这一滚动窗口，仍按实际请求／探针开始时间统计。

保存后，后续统计读取和阈值评估使用新周期，无需重启；账号列表、监控弹窗和说明显示本次统计实际使用的周期。评估频率仍为每 30 秒一次，更改周期不会解除已有监控暂停。

管理员 API 为 `GET /api/v1/admin/settings/account-performance` 和 `PUT /api/v1/admin/settings/account-performance`，请求和响应中的设置结构为：

```json
{"window_minutes": 60}
```

配置使用现有 `settings` 表的 `account_performance_window_minutes` 键持久化，无需新增表或迁移。升级后未配置的安装使用 60 分钟；设置读取失败或存储值不合法时，本次统计／评估返回错误，不以其他周期替代。

触发阈值后，监控使用独立暂停标记停止账号的新调度，不覆盖账号原有的启停、冷却或分组状态，也不终止已经在途的请求。人工解除暂停会同时关闭监控，重新开启前需要明确保存配置。

评估任务每 30 秒调度一次，每轮预算 25 秒；超时或失败后从上轮最后尝试的下一个账号继续，避免列表尾部长期无法评估。账号数量和查询耗时仍会影响一轮完整覆盖所需的时间。

区域发布端在同一数据库快照中读取账号和暂停状态，移除暂停账号后再发布完整快照。暂停查询失败时不发布、不延长旧快照的有效期。区域订阅端在调度、账号详情和并发准入时只使用已认证且未过期的本地快照；缺失账号或快照过期均拒绝准入。控制面也拒绝为已暂停账号发放新区域并发授权或续租。

区域传播受配置的同步间隔、快照有效期及现有授权有效期约束，不能保证控制面提交暂停后所有节点立即同步撤销；不会强行回收已占用的槽位。需要即时停用所有节点时，应使用现有的区域撤销/排空流程。

配置、评估和解除暂停都先锁定未删除账号，再变更监控状态与审计记录，避免软删除并发产生新监控操作。批量指标接口不返回软删除账号。

## 平均缓存

账号列表的「性能 · 近60分钟」列及使用同一组件的阈值弹窗新增「平均缓存」。它跟随全局滚动周期，显示有效请求缓存命中率的算术平均：每条请求先计算 `100 × cache_read_tokens / (input_tokens + cache_read_tokens + cache_creation_tokens)`，再按请求等权平均。`input_tokens` 是已归一化的未缓存输入；这不是按 Token 加权的总命中率。

统计复用性能查询中按请求开始时间筛选的完整成功文本请求；缺少唯一完整耗时记录、失败或不完整请求、媒体请求均不计入。三个输入桶必须非负且总和大于零；没有有效样本显示「未采集」，有效零命中显示 `0.0%`。提示说明包含当前周期和样本数。批量性能响应新增 `avg_cache_percent`（百分比或 `null`）与 `cache_samples`，旧服务缺少字段时前端显示「未采集」。

此项只用于展示，不新增缓存阈值、不改变暂停条件或优先级评分。复用现有批量 SQL，无新增请求、定时任务或数据库迁移。新功能提示使用 `account-average-cache-initial-announcement`，账号列表、阈值弹窗与复用性能组件的优先级分析页共用 ID。

## 上游 HTTP 错误率阈值

账号性能弹窗中的「上游 HTTP 错误率」上下限使用与错误率展示相同的采集器和滚动窗口。错误率为本进程已观测到的上游 HTTP 4xx/5xx 响应数，除以上游 HTTP 2xx–5xx 响应总数，再乘以 100；按收到响应头的时间计算，包含窗口边界。每次重试分别计数，例如同一业务请求先收到 503、再收到 200，错误率样本是 1/2，而非一次最终成功。

采集覆盖通过共用 HTTP 传输的推理 POST，包含使用该传输的探针。收到响应头前的网络失败、取消、本地认证/余额/调度拒绝没有样本；HTTP 200 中的业务错误、不完整流、原生 WebSocket 及绕过该传输的插件路径不在错误统计内。这是上游 HTTP 响应状态错误率，不是全部请求或用户最终失败率。账号名称含 WS 不代表其原生 WS 轮次已经被采集。

配置仍通过账号现有性能监控 API 保存，`config` 新增可选字段：

```json
{
  "enabled": true,
  "tps": {"min": null, "max": null},
  "degradation": {"min": null, "max": null},
  "ttft": {"min": null, "max": null},
  "upstream_error": {"min": null, "max": 25}
}
```

在该例中，观测错误率 28.2% 严格高于 25% 时，下次有效评估会添加 `upstream_error` 暂停原因；等于 25% 不触发。没有样本时不触发，也不把缺失值当 0；有成功响应、失败数为零时的 0% 是有效值，可以触发配置的正数下限。没有新增最小样本数限制，单个响应也可参与判断。

证据仅保留在当前服务进程内，最多保存最近 65,536 条响应及 24 小时。进程重启、容量淘汰或保留时限可能使窗口历史不完整；只要存在有效响应样本，仍按已观测部分评估，不等待完整窗口。弹窗说明和暂停审计保留失败数、总数、百分比、来源、保留起点与 `window_complete`。缺样本、样本过期、后续恢复或重启不会解除已持久化的暂停。

多实例不汇总此指标：只有运行现有后台监控任务的 full 节点参与评估，gateway 节点的本地采样不会自动汇入 full 节点。哪个评估进程取得账号监控行锁，就用哪个进程自己的样本判断；该进程可能与管理员读取页面的实例不同。暂停结果按现有数据库、调度和区域传播规则生效，影响该账号的新调度，而不是仅暂停采集实例。跨实例显示不同样本是这一采集口径的限制，不能当作集群总错误率。对于只在其他进程或原生 WS 上有流量的账号，评估进程可能一直没有可用证据。

旧 JSON 配置缺少 `upstream_error` 时，两侧默认不限制，无需数据库迁移，也不会自动启用监控。回滚旧二进制后该新阈值不再评估；已有独立暂停及显式解除规则仍保留。旧版本整体保存配置可能丢弃未知字段，因此混用版本期间应避免编辑新阈值，升级完成后重新核对配置。新增阈值提示独立于原错误率展示提示，使用稳定 ID `account-upstream-http-error-threshold-initial-announcement`；普通升级不复活已关闭的提示。

回归证据由 `Account performance release regressions` 和主 CI 提供：包括评估轮换、原缺陷反向验证、区域导出失败拒绝、订阅端本地准入、PostgreSQL 指标与软删除并发。测试使用合成数据，不发送真实模型请求。
