# 账号性能监控

账号性能监控按全局配置的滚动周期计算有效样本的 TPS、流式首 Token 耗时和完整质量检测轮次的降级比例，默认使用最近 **60 分钟**。缺失、失败或不完整样本不按零值计算。监控默认关闭，管理员逐账号设置上下限后启用。

在「系统设置 → 网关服务 → 账号性能监控周期」填写统计周期，单位为分钟，范围为 1–1440 的整数，默认 **60 分钟**。所有账号的平均 TPS、首字平均值与探针轮次降智率共用这一滚动窗口，仍按实际请求／探针开始时间统计。

保存后，后续统计读取和阈值评估使用新周期，无需重启；账号列表、监控弹窗和说明显示本次统计实际使用的周期。评估频率仍为每 30 秒一次，更改周期不会解除已有监控暂停。

管理员 API 为 `GET /api/v1/admin/settings/account-performance` 和 `PUT /api/v1/admin/settings/account-performance`，请求和响应中的设置结构为：

```json
{"window_minutes": 60}
```

配置使用现有 `settings` 表的 `account_performance_window_minutes` 键持久化，无需新增表或迁移。升级后未配置的安装使用 60 分钟；设置读取失败或存储值不合法时，本次统计／评估返回错误，不以其他周期替代。

触发阈值后，监控使用独立暂停标记停止账号的新调度，不覆盖账号原有的启停、冷却或分组状态，也不终止已经在途的请求。人工解除暂停会同时关闭监控，重新开启前需要明确保存配置。

评估任务每 30 秒调度一次，每轮预算 25 秒；超时或失败后从上轮最后尝试的下一个账号继续，避免列表尾部长期无法评估。账号数量和查询耗时仍会影响一轮完整覆盖所需的时间。

区域发布端在同一数据库快照中读取账号和暂停状态，移除暂停账号后再发布完整快照。暂停查询失败时不发布、不延长旧快照的有效期。区域订阅端在调度、账号详情和并发准入时只使用已认证且未过期的本地快照；缺失账号或快照过期均拒绝准入。控制面也拒绝为已暂停账号发放新区域并发授权或续租。

区域传播受配置的同步间隔、快照有效期及现有授权有效期约束，不能保证控制面提交暂停后所有节点立即同步撤销；不会强行回收已占用的槽位。需要即时停用所有节点时，应使用现有的区域撤销/排空流程。

配置、评估和解除暂停都先锁定未删除账号，再变更监控状态与审计记录，避免软删除并发产生新监控操作。批量指标接口不返回软删除账号。

回归证据由 `Account performance release regressions` 和主 CI 提供：包括评估轮换、原缺陷反向验证、区域导出失败拒绝、订阅端本地准入、PostgreSQL 指标与软删除并发。测试使用合成数据，不发送真实模型请求。
