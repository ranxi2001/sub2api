# 账号性能统计缓存

账号列表的性能接口 `/api/v1/admin/accounts/performance` 读取共享 Redis 快照，页面请求只查询当前统计周期、有效账号和监控配置，不执行用量／时序明细聚合。首次访问返回 `statistics_status=pending`，随后由页面现有 30 秒轮询取得快照；上游 HTTP 错误率继续读取本进程内存，不等待数据库统计。

## 缓存与回源预算

- 身份：数据库名、统计周期（1–1440 分钟）、账号 ID；窗口更改立即使用另一组缓存。
- 60 秒内复用快照；60–180 秒保留原值并异步刷新；达到 180 秒停止展示旧值。返回真实统计截止时间，不将旧样本伪装成当前窗口。
- 每个实例最多 512 个待刷新账号，同一账号／窗口合并排队；单个 worker 每次查询一个账号，单次回源最多 5 秒（只读事务内语句预算 4.5 秒、锁等待 500ms、work_mem 8MB，禁查询并行），避免某个热点账号拖垮同页其他账号。
- 同一数据库的实例通过 Redis 10 秒租约限制显示统计回源并发为 1。发布和释放都核对租约所有者；旧 worker 无权覆盖新所有者的快照或释放其租约。
- Redis 操作预算 300ms。缓存或锁不可用时不执行同步明细扫描。单次统计失败保留已有快照，并设置跨实例 30 秒失败退避。
- 缓存不含密钥、请求正文、账号名称或原始 trace，只包含聚合数值、样本数和时间。Redis 数据随 180 秒 TTL 清理。

## 正确性与边界

阈值配置、revision、暂停代次和账号删除状态每次从数据库读取。阈值评估、自动停调和优先调度保持原有实时证据路径，不使用页面的旧缓存授权调度。上游错误率不跨进程汇总，也不写入 Redis 统计快照。

聚合 SQL 只投影必要数值字段，用一次记录展开提取时序 JSON，再物化已确认成功的窄记录，避免重复解析整块时序。继续要求唯一 trace、完整成功文本请求、有效实际开始时间；缺样本仍为 null，质量轮次、媒体排除和缓存算术平均口径不变。

这项改动限制页面流量引发的查询次数和并发，不是持久化分钟预聚合。第一次访问、长时间未访问或统计周期变更仍需读该账号的原始窗口。超大单账号窗口可能继续超过 5 秒预算，界面会给出该账号不可用状态并退避；没有生产负载对照时不宣称完全消除所有慢查询。监控评估和优先调度的历史查询负载另行评估。

无数据库迁移、无新增配置。新状态字段为 API 增量字段；建议前后端一起部署以展示准备中、快照截止与更新中状态。回滚二进制后旧 Redis 项会自然过期，无需清理全站缓存。

## 回归入口

- `account_performance_display_cache_test.go`：冷读不等待回源、实时暂停状态、浏览器取消隔离、跨实例锁、失效所有者发布保护、失败退避、窗口／数据库隔离、硬过期、Redis 故障、队列与停止。
- 既有 `account_performance_integration_test.go`：迁移后的 PostgreSQL 中验证 SQL 边界、完整成功样本、重复 trace、缺样本、质量轮次及原有指标口径。
- `AccountPerformanceCell.spec.ts`：准备中／故障期间保留本进程上游错误率，旧快照标注时间且无质量样本不伪造 0%。
