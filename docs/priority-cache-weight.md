# 优先调度缓存权重

智能运维 → 优先调度的性能列展示账号平均缓存命中率，使用与账号管理相同的数据和全局性能窗口。百分比是有效请求缓存率的算术平均，不是 Token 加权平均；它跨账号内的模型和分组汇总。利润用量窗口不会改变缓存统计范围。

展开「调度配置」后可设置「缓存命中率权重」，所有模式均适用。允许 0–100 的数值，默认 0，旧配置也按 0 读取。0 表示不参与评分；显式调高后，缓存率越高，该项得分越高。旧客户端未提交 `cache_weight` 时保留现值，显式提交 0 才关闭。

缓存分数 = 平均缓存百分数 ÷ 100。原来的质量、首字、TPS、成本分数与缓存分数一起按各项权重之和归一化，再应用原有错误率惩罚。例：其余权重总和为 100、原基础分为 70，缓存权重 25、平均缓存 80% 时，新的基础分为 `(70 × 100 + 80 × 25) ÷ 125 = 72`。权重是相对权重，预设模式的原四项数值保持不变。

样本数须达到已有「最小样本数」设置。缺失、无效或样本不足时使用中性分 0.5，并在开启缓存权重时标记「缓存样本不足」。已采集的 0% 与无数据不同。缓存率 ≥80% 为绿色、50%–80% 为黄色、20%–50% 为橙色、低于20% 为红色；无数据或请求失败时为灰色。颜色仅表示展示档位，不改变连续缓存评分公式，也不新增账号停调阈值。

本功能只影响优先调度评分，不添加账号性能停调阈值。资格、并发、RPM、风险分层、优先级、利润门禁、会话粘性及原有归属保护继续生效；高缓存分不能绕过这些门禁。低缓存不自动停用账号。缓存偏好不保证未来请求命中，不清缓存、不调用真实模型。

配置沿用管理员优先调度 API 和设置存储，无数据库迁移。配置变化按既有运行时刷新机制生效；设置为 0 恢复原四项评分。旧二进制不识别新字段，回滚后不使用缓存权重。

UI 将「探针轮次降智率」统一显示为「降智率」，质量运维及关联状态检测入口使用「质量检测」。仍只统计完整、结论明确的检测轮次；不代表全部业务请求的降智率。后端字段名、API 和统计公式不因显示名称改变。
