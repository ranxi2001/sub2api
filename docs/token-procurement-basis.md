# Token 采购基数

管理员核对上游账单和本站价卡后，可以通过账号管理 API 的 `extra.token_procurement_basis` 指定倍率适用的价格。

| 值 | 利润报表的估算成本 |
| --- | --- |
| `account_stats`（默认） | 账号统计基数 × 采购倍率。可用现有渠道的账号统计定价规则录入独立的上游价卡。 |
| `standard_charge` | 本站倍率前标准收费基数 × 采购倍率。适用于本站标准价卡与该账号的上游采购基准一致的情况。 |

例如，已核实的账号可以通过 `POST /api/v1/admin/accounts/bulk-update` 更新：
```json
{"account_ids":[123],"extra":{"token_procurement_basis":"standard_charge"}}
```
当标准基数为 100、账号统计基数为 15、采购倍率为 0.35 时，标准基数估算成本为 35。设置作用于账号计费倍率为 1 的 Token 请求。已匹配的逐笔结算金额优先；图片采购、视频、按次计价、网关和已有非 1 倍账号计费沿用各自的计价规则。

新请求记录基数类型和当时的采购倍率，后续编辑不会改变这些请求的估算。旧请求缺少基数类型时，报表采用该账号当前的基数配置；已有快照的倍率仍取请求记录。没有快照和显式采购倍率时，成本显示为待核实。切换基数会重估该账号符合条件的历史记录，适用前应核对拟查询账期的上游价卡。
