# Token 采购基数

管理员核对上游账单和本站价卡后，可以通过账号管理 API 的 `extra.token_procurement_basis` 指定倍率适用的价格。

| 值 | 利润报表的估算成本 |
| --- | --- |
| `account_stats`（默认） | 账号统计基数 × 请求计费倍率。计费倍率为 1 时使用已保存的采购倍率。可用现有渠道的账号统计定价规则录入独立的上游价卡。 |
| `standard_charge` | 本站倍率前标准收费基数 × 采购倍率。适用于本站标准价卡与该账号的上游采购基准一致的情况。 |

例如，已核实的账号可以通过 `POST /api/v1/admin/accounts/bulk-update` 更新：
```json
{"account_ids":[123],"extra":{"token_procurement_basis":"standard_charge"}}
```
当标准基数为 100、账号统计基数为 15、采购倍率为 0.35 时，标准基数估算成本为 35。已匹配的逐笔结算金额优先。图片采购、视频、按次计价和网关各有独立计价规则。

新请求记录基数类型和当时的采购倍率，后续编辑不会改变这些请求的估算。旧请求缺少基数类型时，报表采用该账号当前的基数配置；已有快照的倍率仍取请求记录。旧 Token 请求选择标准基数时，优先取请求采购快照里的倍率。没有采购快照且请求记录了非 1 倍账号倍率时，采用该笔历史倍率。例如标准基数 100、账号统计基数 15、当时账号倍率 0.33，估算成本为 33。没有采购快照且账号倍率为 1 时，使用当前显式采购倍率。缺少所需倍率时显示为待核实。切换基数会重估该账号符合条件的历史记录，适用前应核对拟查询账期的上游价卡。
