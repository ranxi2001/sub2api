# OAuth 首次配置后的 API Key 处置

入口：智能运维 → 自动配置 → “OAuth 账户首次配置”右侧，“账号并发升级”下方。默认关闭；与首次配置一起启用后，仅新建并成功完成首次配置的同平台 OAuth 账号触发。导入更新、重新授权和手动编辑不触发。

例如，选择“临时暂停调度”、延迟 5 分钟、暂停 180 分钟，再按分组筛选并勾选 API Key 账号。新 OAuth 账号保存后会安排关闭任务，实际关闭 3 小时后安排恢复。“关闭调度，不自动恢复”只安排关闭任务。0 分钟在下次后台轮询执行；后台每 30 秒轮询，积压或失败重试可能进一步延迟。

“所选分组内全部 API Key 账号”在每次新 OAuth 创建时解析同平台 API Key 母账号并去重；手动模式使用勾选名单，最多 1000 个，可跨页选择。关闭的是账号全局调度，因此会影响账号的其他分组；任务创建后不再动态扩大账号范围。

账号创建、分组绑定和定时任务在同一数据库事务提交。已有待执行定时任务、已关闭调度、停用、过期或删除的账号会跳过。连续导入不会覆盖正在等待的任务或延长暂停。账号列表直接显示动作、时间、时区、一次性状态；可通过已有定时任务面板取消。

暂停后的恢复仅适用于本次任务实际关闭、且之后未被修改的账号。手动调度操作会取消待执行任务；其他账号更新也会让恢复任务跳过。调度开关之外的冷却、额度和质量限制保持原有行为。若取消关闭任务，配对恢复不会开启该账号。

关闭或修改本规则不会取消已经创建的任务；需要在账号定时任务中取消。兜底处置等其他自动策略仍可开启同一账号，不承诺与本规则互斥。本功能不改变已在途请求，也不保证 OAuth 请求吞吐提升。

不新增数据库迁移；使用已有 `account_schedulable_timers` 和审计表，系统任务的 `requested_by` 为 0，原因记录触发的 OAuth 账号 ID。回滚到不认识此来源标记的旧二进制前，应取消这些待执行任务，尤其是恢复任务，避免旧版本按普通定时开启任务执行。
