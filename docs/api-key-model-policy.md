# 单个 API Key 的模型映射与推理强度

管理员可在「用户管理 → API Keys → 密钥模型与上下文设置」配置某一把密钥。管理员编辑自己的密钥时，编辑窗口也提供同一入口。普通用户没有配置入口，普通密钥创建、编辑接口也不接受这些管理字段。该窗口还支持[单个 API Key 的长上下文开关](api-key-long-context-control.md)。

例如，为某个 Key 添加 `gpt-6.1-sol → gpt-5.6-sol`，并将推理强度设为 `high`。该 Key 的匹配请求会使用 `gpt-5.6-sol` 和固定强度，其他 Key 保持原行为。模型 ID 应填写上游实际支持的名称。

模型映射采用区分大小写的精确匹配，仅执行一次，不匹配的模型保持原名。最多配置 100 条，每个模型 ID 为 1–200 UTF-8 字节，且不包含空白或控制字符。删除全部映射后保存可清除映射。

推理强度的默认选项为「跟随客户端」，沿用原有客户端和分组规则；选择具体强度会覆盖客户端值和分组强度映射，但仍接受分组强度上限及其降级/拒绝规则。上游仍需支持所选强度，界面不会推断每个模型的能力。

## 请求范围与优先级

- 模型映射用于 Responses（含 compact）、Chat Completions、Messages 及 Messages 的 token 计数入口；图片、音频、embeddings 和模型发现接口维持原行为。
- 固定推理强度用于 OpenAI 兼容请求，包括 Responses HTTP、WebSocket 的每个请求轮次、Chat Completions，以及转发到 OpenAI 的 Messages 桥接请求。
- 模型先经过 Key 映射，再进入现有分组、合成路由、渠道和账号映射。原请求模型和 Key 映射目标都需通过分组与用户模型权限校验。HTTP 多分组可用性检查使用映射目标；WebSocket 沿用握手时选定的分组，在该分组内对每轮模型映射、权限和账号资格进行检查。
- 配置保存会使对应 Key 的鉴权缓存失效。新的请求取得新配置；正在执行的请求保持其请求快照。排队请求和 WebSocket 下一轮重新校验时发现配置变化会提示重试，长连接应重新连接以取得新配置。
- 用量保留客户端原始请求模型和实际转发模型。计费依据本次请求实际应用的映射记录；使用请求模型计价时，以 Key 映射后的模型查价。未应用映射的接口保持原价，配置在请求入场后变化也不改变本次计费。显式渠道计价来源仍生效，包括 Key 将 A 映射到 B、渠道再将 B 映射回 A 的情况；无渠道映射时，不会回退到 Key 改写前的别名价格。

## 管理接口

`PUT /api/v1/admin/api-keys/{id}`，需要管理员身份。请求示例：

```json
{
  "model_mapping": {
    "gpt-6.1-sol": "gpt-5.6-sol"
  },
  "reasoning_effort": "high"
}
```

省略字段表示保留原值；`model_mapping: {}` 清空映射，`reasoning_effort: ""` 恢复默认行为。返回沿用 `{ "api_key": { ... }, "auto_granted_group_access": false }` 的结构。

同时提交策略、分组与 `reset_rate_limit_usage: true` 时，通过一次仓库更新保存，失败后保留原策略、分组和限速用量；认证及用量缓存仅在保存成功后失效。

迁移 `327_api_key_model_policy.sql` 增加两个默认空值字段，已有密钥保持原行为。仓库更新使用字段掩码，普通用户修改名称、分组、额度时保留管理员策略。鉴权缓存和区域快照包含这些策略，区域鉴权部署需重新发布当前版本的快照（包含长上下文开关的版本为 v33）；映射在缓存读取和分组副本中独立复制。

## 验证范围

新增测试覆盖配置保存与清除、参数校验、用户更新隔离、鉴权缓存与区域快照、模型权限、非递归映射、HTTP 改写、WebSocket 多轮强度覆盖和映射计费。验证使用本地测试数据；实际供应商的模型支持情况和线上部署需在相应环境单独核验。

本次本地验证：96 个相关前端测试、前端 ESLint、前端完整构建（含类型检查）通过；管理员接口、存储与缓存、网关转换和计费定向测试通过；中间件与路由包完整单元测试通过；`go build -tags embed ./cmd/server` 通过。

转发验证经过真实中间件、handler 和网关代码，由本地 mock 上游接收最终 payload：15 组 HTTP 场景逐次交替 Key A/B/A，覆盖 Responses、compact、Chat、Messages，以及原生/透传模式；两种 WebSocket 模式覆盖首轮、后续轮、字段缺省和配置变更后的重连。管理员权限测试覆盖匿名、普通用户、观察员和管理员；SQLite 事务失败用例验证组合操作回滚。

内置浏览器使用真实 Vue 组件、项目样式和内存 API 示例，验证了窄屏/桌面布局、嵌套弹窗、保存回显及另一 Key 的配置隔离；控制台无错误。预览为本地测试数据，没有修改线上密钥。

Windows 上既有区域快照落盘测试 `TestRegionalAuthLocalReplacementRevocationAndRestore` 在目录 `Sync()` 报 `Access is denied`。使用 HEAD 原版测试文件的 overlay 运行同样失败；该平台持久化代码保持原样。新增独立测试 `TestAPIKeyRegionalModelPolicyExportRoundtrip` 已验证真实导出、校验、反序列化、密钥隔离及旧缓存版本拒绝。尚未执行 PostgreSQL 生产迁移或调用真实供应商。
