# New API 上游钱包与分组查询

管理员可在账号列表的「上游渠道声明」列点击「不支持」，为 API Key 账号配置 New API 查询。配置后的倍率和余额使用其他账号的同一显示格式；点击倍率或状态文字可编辑配置，分组倍率的口径说明位于悬浮提示中。已有 Sub2API 声明查询继续使用原接口；未配置 New API 授权的账号也继续使用原探测逻辑。

## 配置与使用

1. 在上游 New API 的个人设置中生成**系统访问令牌**，并确认该用户的 ID。这里需要用户管理接口的授权，调用模型的 API Key 不能代替它。
2. 在配置弹窗填写上游用户 ID 和系统访问令牌，勾选需要同时配置的同站点账号，点击「预览」。不需要手动填写分组名称：服务会匹配每个账号已有的 API Key，读取其令牌分组。
3. 确认钱包余额、Key 匹配及分组结果，点击「验证并保存」。保存会重新验证所有所选账号；任何一个不匹配时，都不会部分保存。脱敏 Key 存在歧义时，选择对应令牌，再通过上游密钥接口核实。
4. 配置后可点击刷新查询，或使用现有自动探测设置。保存会打开账号级自动探测；后台定时刷新还受全局探测开关与间隔控制。

同站点、同上游用户的授权只加密保存一份。新填入的系统访问令牌会更新这份共享授权。已有授权时可留空复用；勾选的账号可以属于不同分组，但必须由该上游用户拥有。清除当前账号配置不会清除其他账号的绑定。

站点按协议、主机、有效端口与路径区分，忽略默认端口、末尾斜杠和末尾 `/v1`。例如 `https://example.com/tenant/v1` 与 `https://example.com/tenant/` 属于同站点；`/other/v1`、HTTP 地址或其他端口属于另一站点。同域名的不同用户不会自动共用钱包。

## 金额与倍率口径

钱包取自 `/api/user/self` 的 `quota`，除以 `/api/status` 公布的正数 `quota_per_unit`，得到原始 USD 账面额度。账号余额、配置预览与运营余额列表再按上游 `quota_display_type` 显示：`USD` 保留原值；`CNY` 乘 `usd_exchange_rate`；`CUSTOM` 乘 `custom_currency_exchange_rate` 并使用 `custom_currency_symbol`。例如原始 12.34、CNY 汇率 7.3，显示为 `90.08 CNY`。这是用户钱包余额，不能由 Key 剩余额度代替。

上游未提供币种、使用 token/未知显示模式，或者汇率/自定义单位无效时，保留原始金额并明确标记 USD，不猜测汇率。转换使用上游配置，不调用外汇服务，不受采购成本的「应用美元汇率」开关影响。已有快照在下一次成功查询后更新。

快照的 `remaining`、`wallet_balance` 与 `unit` 使用同一显示口径，另保留 `raw_wallet_balance`、`raw_unit=USD`、`display_exchange_rate`。已有 USD 余额告警继续比较原始 USD，不会把相同阈值解释成人民币；新规则可以按当前显示单位设置。失效/过期快照仍不触发恢复通知。升级不会改写告警阈值；回退旧二进制前需检查新增非 USD 规则，旧程序不具备 USD 原值兼容比较，待旧程序下一次采样后重新核对规则单位。

分组取自该用户拥有的 `/api/token/` 令牌记录，倍率取自相同用户授权下的 `/api/pricing`。分组倍率只是分组计费系数，不包含模型价格等因素，**不会自动修改本地账号计费倍率**；采购成本倍率按下述默认规则换算，可逐账号关闭美元汇率或成本同步。动态 `auto`、跨组重试、多个路由分组或无法读取的分组倍率会显示无固定倍率；仍可显示有效的钱包余额。

## 采购成本倍率换算

每个账号的「应用美元汇率」默认开启。系统复用账号所属平台既有的 `cn_provider`：true 使用 ×1，false 使用 ×7；取消勾选后使用 ×1，无需填写或选择系数。现有成本自动同步开关仍独立生效，显式关闭成本同步的账号保留手动成本。

例如非 CN 平台的上游分组倍率 0.1，在默认开启汇率时换算成成本倍率 0.7，关闭汇率时为 0.1；CN 平台的 0.7 始终为 0.7。系数 7 是固定值，不读取外汇接口，也不转换钱包余额或逐模型价格。分类只看账号平台属性，不猜测账号名、模型别名或上游分组币种；当前 CN 平台为 Kimi、智谱、DeepSeek、MiniMax。

账号列表的「上游渠道声明」按当前账号的美元汇率设置展示和排序。非 CN 平台开启汇率时，原始分组倍率 0.1214 换算为 0.8498，列表显示 0.85x，悬停可见原值和换算结果。手动维护采购成本时也可以查看这个声明值。

预览显示原始分组倍率和换算后的成本。成本同步开启时，验证并保存立即写入 `extra.cost_multiplier`，后续成功探测自动更新。自动/跨组路由、缺少固定倍率、查询失败或超出成本字段范围时保留已有成本。关闭美元汇率仅停用 ×7 换算，不停止按 ×1 同步成本。

汇率开关保存在 `extra.new_api_apply_usd_rate`，缺失或 true 为应用，false 为不应用；不新增数据库迁移。升级后已有 New API 账号也按默认应用处理，但不会覆盖其显式关闭成本自动同步的设置。客户售价及账号计费倍率不变。回退旧二进制会忽略新开关，已写入的成本值仍保留。

## 部署、权限与保护

- 默认不配置 New API 授权。配置接口仅限管理员，账号列表不返回系统访问令牌或密文。令牌请求体遵循现有审计脱敏规则。
- 需要固定的 `totp.encryption_key`（环境变量 `TOTP_ENCRYPTION_KEY`），使用现有 SecretEncryptor 加密。自动生成的临时加密密钥不能用于保存授权。备份时必须保留这个固定密钥，否则加密数据不能解密。
- 迁移 `265_new_api_site_authorizations.sql` 增加授权表与账号绑定表，不迁移或删除既有业务数据。数据库备份应包含这两张表。
- 上游必须兼容 New API 用户资料、站点状态、令牌列表接口；读取分组倍率还需要 pricing 接口。受限或自定义部署可能无法完成部分查询。
- 请求沿用账号自身代理、TLS 与 URL 安全策略，禁止自动重定向，并限制超时、分页与响应大小。账号凭据或共享授权更新后，过期探测不能写回旧结果。
- New API 管理查询默认使用 `User-Agent: Sub2API-Upstream-Probe/1.0`，账号显式配置的请求头覆盖仍优先。部分上游网关只在令牌列表路径拒绝 Go 默认客户端标识；因此状态、钱包和价卡接口返回 200，不代表令牌列表也已通过。
- 回退二进制不会撤销数据库迁移。旧程序可忽略新增表；恢复到迁移前数据状态需要恢复对应数据库备份。更换固定加密密钥应另行安排密文重加密。

## 接口与验证

管理员接口位于 `/api/v1/admin/accounts/:id/upstream-billing-probe/config`：GET 获取无密钥的配置与同站点账号，POST `/preview` 验证，PUT 原子保存，DELETE 解除当前账号绑定。

请求包含 `user_id`、可选 `access_token`、`account_ids`，以及歧义时的 `token_selections`（账号 ID 到上游令牌 ID 的映射）。账号、站点或共享授权在验证期间改变时，需要重新验证。

自动化测试覆盖钱包与 Key 额度隔离、用户归属、分页、脱敏冲突、共享授权隔离与原子写入；真实站点仍需使用管理员提供的用户管理授权验证其接口兼容性。
