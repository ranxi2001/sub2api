# OpenAI OAuth 账号代理

普通 OpenAI OAuth 与 BPS OAuth 账号均可在原有「代理」字段中切换**单代理**或**按请求分散**；普通父账号绑定独立 SIWC 授权并选择 SIWC API 后，也使用同一入口。BPS 或 SIWC 设置不另设多代理入口。管理员为账号手工选定多个现有代理，不同逻辑请求优先使用该账号当前在途请求较少的代理；没有空闲代理时允许复用。代理数量不改变账号总并发上限，也不代表上游会提高该账号的并发或吞吐额度。实际效果需要在自己的账号中逐步试用。

同账号使用多个 IP 可能增加异常验证、限流及账号限制风险，不保证提升吞吐或降低风险。先控制账号总并发；需要恢复单出口时明确切回 single 并核对原代理，或停用账号。连接检测成功不能证明上游许可或长期风险。

## 配置账号

1. 在「IP 管理」准备需要使用的代理，确认其启用状态、有效期及连通性。不同代理记录可能连接同一个公网出口，动态代理也可能随连接变化；本功能不保证公网 IP 唯一。
2. 新增或编辑普通 OpenAI OAuth 或 BPS OAuth 账号，在原有「代理」字段选择「按请求分散」，多选该账号允许使用的代理。已绑定 SIWC 授权的普通父账号沿用此配置。保存后重新打开编辑页，核对请求协议、模式和所选代理；原 `proxy_id` 保留，切回单代理时继续使用原单代理配置。
3. 保持所需的账号总并发上限。例如总并发为 6、健康代理为 3 时，在请求重叠且负载相当的条件下尽力接近 2 / 2 / 2 分布；请求耗时不同、到达顺序不同会影响实际分配。
4. 先用隔离实例检查保存、转发、取消及故障行为，再安排自己的账号试用。新增的其他代理不会自动加入已有账号的代理组。

### 选择、查看关联账号与测试连接

代理组沿用单代理选择器的展开列表：第一行显示代理名称，第二行显示协议、主机与端口，右侧提供测试连接按钮。地址不包含认证凭据。列表支持搜索代理名称、地址及已经加载的关联账号名称和 ID。

展开后可批量选择当前搜索结果、选择未被账号配置使用的代理、反选当前结果，也可分别使用“清空当前结果”和“清空全部”。全选、仅选未占用、反选及清空当前结果只影响搜索结果中的可用代理，保留筛选范围外及已失效的选择；仅选未占用还会保留关联未知的选择。“清空全部”则移除所有选择，包括隐藏、失效和缺失项。停用、过期的代理不能新增选择，原来已选但失效或缺失的项仍可单独取消。目录加载中或失败时不会将已选项误报为已删除；加载失败可重试。

每条代理显示关联账号的名称与 ID，并在编辑时标记当前账号。这里的“使用”表示**配置关联**：包括传统单代理绑定与账号按请求代理组，同一账号只计一次，已删除账号不计入。新配置优先：显式 single 不再引用被其覆盖的旧 BPS 组；没有新模式时，暂时关闭 BPS 但保留的旧组仍算关联。关联不表示账号正在产生流量。详情未加载或加载失败时显示未知，可重试，不会当作未被使用。被代理组引用的代理同样受到删除保护，须先从相关账号配置中移除。

单条测试与批量测试复用现有连接检测接口，展示成功或失败，以及接口返回的延迟和国家信息。批量测试只检测当前搜索结果，最多同时执行 5 项，同一代理不会重复排队。测试按钮不会改变选择；检测成功也不等于该代理可以满足真实上游账号的全部请求。

账号 `extra` 的相关字段如下。下面是字段结构示例，数字 ID 只属于当前数据库，不能直接用于跨库迁移：

```json
{
  "openai_proxy_mode": "request",
  "openai_proxy_ids": [101, 102, 103]
}
```

| 字段 | 含义 |
| --- | --- |
| `openai_proxy_mode` | `single` 为原单代理路径，`request` 为按请求分散。只要字段存在就优先采用新配置；显式 single 压制旧 BPS request。 |
| `openai_proxy_ids` | 新配置的账号代理组，仅供当前数据库内引用。request 必须具有非空有效选择，不沿用旧组补齐。 |
| `openai_excel_bps_proxy_mode` / `openai_excel_bps_proxy_ids` | legacy BPS 配置。仅缺失新模式时兼容；原 `session` 及来源配置保留，旧 request 仍按原 BPS 启用条件生效。 |

新 request 配置独立于 BPS 开关，对普通 OAuth 及其已绑定的 SIWC 协议也生效；它不改变 BPS 或 SIWC 的模型、授权和额度条件、账号总并发或既有调度规则。关闭 BPS 不会关闭显式的新 request 配置。未知模式、非法代理 ID、空 request 组，以及新建或变更组中不存在、停用或过期的代理会在保存时明确报错。新模式为 null 或非法值不会自动退回 legacy、单代理或直连。

旧入口未修改代理配置时保留原配置；不要通过删除新字段来表达切回单代理，否则旧 BPS request 可能重新成为生效配置。切回单代理应明确保存 `openai_proxy_mode: single`。已保存组后来失效时，允许不变更该组的无关编辑或关闭模式；实际请求仍只按当前可用组转发，不能借此绕过失败策略。新 request 配置只支持普通 OpenAI OAuth 父账号（含已绑定独立 SIWC 授权）与 BPS OAuth；PAT、Agent Identity、shadow 及非 OAuth 账号不启用该模式，身份型 SIWC 也不会因此获得推理能力。

导出携带代理时，新配置使用账号顶层 `openai_proxy_keys` 映射到目标库代理；legacy 配置继续兼容 `bps_proxy_keys`。导出移除来源数据库的数字组 IDs，导入不接受用来源数字 ID 代替映射键。组键使用版本化 SHA256 身份，精确包含协议、主机、端口、用户名和密码；凭据中的分隔符和空格不合并。目标映射只来自实际存在或实际创建的代理，不信任导入文件的任意别名。旧单代理仍使用原 `proxy_key` 规则；若其导入因键碰撞未创建正确身份，代理组账号明确失败，须核对后手动重配。选择“不导出代理”不会自动关闭 request 模式，因缺少映射键而无法直接恢复该账号，须先在隔离副本中明确重配或停用。绑定本机 Mihomo 节点的代理不能按监听端口跨库移植：包含此类组的带代理导出会报错，导入映射到目标 Mihomo 节点也会报错，必须手工重配并核对出口。

导入沿用现有逐项、非原子流程：代理先处理，账号后校验。因此账号导入失败不代表整批零修改，代理可能已经创建或更新。先在隔离副本验证，并核对 `AccountFailed`、`ProxyCreated`、`ProxyReused` 与 `Errors`；HTTP 200 只表示批次已处理。

## 请求如何分配

- **按逻辑请求选择。** 同一会话的不同逻辑请求可以使用不同代理。一次生成以及完成它所需的附件上传、生成和受支持的修正流程保持同一出口；不是每个 TCP 连接或附属操作重新选代理。
- **只使用账号所选范围。** 根据当前有效的代理成员快照、有效期与健康状态筛选候选。禁用、删除等数据库变更经过后台快照刷新后生效，不能把保存成功理解为所有实例立即停止选择该代理。全组没有可用出口时返回明确错误，不直连、不借用组外代理。
- **少量出口可以复用。** 在途数的选择和占用一起完成，优先最空闲候选；平局时轮转。一个逻辑请求结束、取消或失败后释放占用。
- **已发送请求不跨出口重放。** 不能以换 IP 的方式重发可能已被上游接受的请求；仅沿用明确未发送等安全条件下的故障切换。
- **单实例内尽力分散。** 账号总并发继续使用既有共享额度；多实例分别维护代理负载，不承诺整个集群的全局最少在途分配。同一个代理可能同时被不同实例选中。

旧 BPS 会话固定模式保留原有语义，不会因本次升级自动切换为按请求分散。其他平台不在本功能范围。

### 协议、授权与维护边界

| 操作 | request 模式行为 |
| --- | --- |
| 非 SIWC 的 Responses、native/passthrough、Chat Completions、Messages、Images、账号测试 | 经 HTTP/SSE 入口建立请求级出口；受支持的修正、继续、附件与该逻辑请求同出口。Images 沿用已有断开后仍完成出图/计费的生命周期。此行不扩展 SIWC 的端点支持。 |
| SIWC Responses、Chat Completions、Messages、账号测试 | 已绑定普通父账号的 SIWC 授权经现有 HTTP/SSE 与兼容入口转发到官方 Responses 端点，获取 token 前建立请求级出口；请求触发的 SIWC token 刷新与推理保持同一出口。仍使用独立 SIWC 凭据及请求头规则，不改走 Codex、BPS 或插件。 |
| SIWC Images、`/responses/compact` 等原本不支持的端点 | 继续拒绝；按请求分散只改变出口选择，不增加协议能力。 |
| 远程 token 计数 | 使用账号所选组；SIWC 及其他本地估算分支不发上游请求。 |
| 真实 WebSocket | 明确拒绝；HTTP 路径关闭自动 WS 加速，不承诺逐消息换出口。 |
| 原 OAuth 账号首次 2FA 导入 | 独立接口尚不能绑定组，request 模式明确阻断；先用 single 完成导入，再编辑启用 request。纯 session 导入只本地转存，可以直接保留 request 配置。此限制不等同于 SIWC 侧授权的密码/TOTP 流程。 |
| 固定授权连接、managed connections、固定出口 ticket | 与 request 配置冲突时明确失败，不覆盖固定出口约束。 |
| OAuth 授权与 callback | 同一授权 session 固定出口；callback 按当前有效组复核原出口。移组、失效或从 single 切到 request 后原出口不在组内均失败，不另选出口换码。SIWC 共享 session 同样检查。 |
| token 刷新、模型目录、quota、Excel/SIWC、TOTP、session export 等独立维护 | 使用账号组内有效出口；推理请求触发的刷新继承该逻辑请求出口。独立维护操作不承诺与另一次推理选到同一代理。 |
| 自动重新授权 | request 仅允许 local engine 与 account proxy source；其他来源或远程 engine 明确失败，不使用组外代理。 |

推理的在途租约与维护的组内校验用途不同；维护操作没有额外增加账号总并发额度。全部候选不可用或存储、配置校验失败时，维护同样报错，不回退直连或原 `proxy_id`。

### 代理变更与快照新鲜度

后台通过 `ListActive` 获取 IP 管理中的活动代理，按 15 秒刷新间隔更新成员快照；成功结果才更新 request 模式的快照成功时间。禁用或删除会在后续成功快照中移除，已有逻辑请求继续使用其已获得的租约，不在请求中途改出口。获取租约时还会再次检查快照中记录的到期时间和当前健康状态。

按请求分散要求最近一次**成功**快照的年龄小于 30 秒。没有成功快照，或年龄达到 / 超过 30 秒（`age >= 30s`），新请求会收到 `selected_pool_stale` 错误，不会继续使用旧成员、直连或借用组外代理。30 秒包含一次 15 秒刷新窗口以及查询、账号查找和预热工作的余量；它不是“数据库修改后立即失效”的承诺。数据库查询失败不会重置成功时间，因此不能无限沿用旧名单。旧 session 模式的既有语义不因这个 request 模式的新鲜度门限而改变。

## 升级与验证

本功能通过现有账号 `extra`、代理目录和缓存保存配置，不要求为账号代理组新增数据库表。升级目标同时包含其他功能时，仍须检查该版本的迁移、Worker 与共享 Redis 兼容说明，不能因为本功能没有新表而跳过数据库备份。

升级前保存当前产物的版本、完整源码 commit、镜像 ID/digest 或二进制摘要，并备份数据库、配置与加密密钥。前后端应来自同一整合版本；共享账号、调度状态与 Redis 的实例应统一升级，避免旧实例忽略新 request 配置而使用单代理或直连。保留上一个已验证产物和恢复步骤。

先在隔离环境检查以下行为，再将包含本功能的版本接入流量：

1. 缺失新字段的账号保持旧行为；legacy BPS request 可用，显式 single 压制旧 request，原 `proxy_id`、账号总并发与 BPS 来源配置保留。
2. 普通 OAuth、BPS 与普通父账号已绑定的 SIWC 均在原代理字段提供唯一入口；单/多切换、保存重开、请求协议、缓存刷新、备份映射、账号关联与删除保护一致。
3. 使用本地假上游和受控代理观察并发分散、账号隔离与总上限不增加；全组故障时直连和组外发送均为零。
4. 附件、修正、继续和请求触发刷新同出口；完成、取消、错误、EOF、Close 及流中断释放在途占用，已发送请求不新增跨出口重放。
5. 授权 callback 固定原出口并复核当前组，包括改组、single→request、SIWC 共享 session；模型目录、quota、token 与其他受影响维护不直连或走组外。
6. WS、原 OAuth 账号首次 2FA 导入、fixed/managed connection 和不支持的自动重新授权来源明确失败；受支持的 HTTP/SSE、Images 与账号测试遵循组配置。SIWC 单独检查 Responses、Chat Completions、Messages 的组选定出口及请求触发刷新同出口；Images、compact 和 WS 仍拒绝。

代理变更验收需观察各实例最近一次成功快照与真实转发：下一次成功刷新后，不再为新请求选择被停用或删除的成员；数据库持续失败且成功快照年龄达到 30 秒时，返回 `selected_pool_stale`。单次保存成功或等待固定时长不能代替该观察。

按[贡献指南](../CONTRIBUTING.md#按改动范围验证)执行受影响范围检查并记录失败、跳过和未验证项。页面交互、服务单元测试、本地代理网络验证与真实外网账号试用分别证明各自范围；短期测试不能证明长期吞吐改善。

## 回退

1. 停止为相关账号接收新请求，等待已有生成、附件操作和流式响应排空，确认实际请求与租约已结束后再切换版本。
2. 若目标旧版本不识别新模式，在仍支持本功能的版本中先停用相关账号，或明确切回已经验证可用的 single 配置并核对 `proxy_id`。严格禁止直连时优先停用账号；不能假设旧程序忽略新字段后仍遵守 request 的失败策略。不要删除新模式字段来表达关闭，否则 legacy BPS request 可能重新生效。
3. 统一切回已保存的产物与兼容配置，核对实际版本、账号模式和出口行为后再恢复接入。共享 Redis 的槽位 TTL 变化须遵循[统一 drain 要求](../deploy/README.md#api-key-并发槽位-ttl-与升级切换)，不能通过清空 Redis 代替排空。
4. 本功能使用的 extra 配置和导入映射不会因回退二进制自动撤销。若升级同时应用了其他数据库迁移，迁移仍为 forward-only；恢复依据经过验证的数据库备份或补偿方案，不能承诺只换镜像即可回退。已经应用的迁移不可修改。

参见[数据库迁移说明](../backend/migrations/README.md)和[部署迁移说明](../deploy/README.md#database-migration-notes-postgresql)。再次启用 request 前，重新核对代理有效性、账号兼容条件和所有实例的运行版本。

请求代理功能与账号配额分别验收；单进程出口分配不能代替共享账号并发上限的 Redis 验证。
