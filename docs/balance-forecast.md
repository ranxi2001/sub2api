# 余额耗尽预测已移除

余额耗尽预测的后台扫描、设置面板、新功能提示和 `balance.forecast` 邮件事件已移除。服务启动不再创建预测任务；数据库中残留 `balance_forecast_enabled=true` 也不会启动它。按金额阈值发送的余额不足提醒、余额扣减和计费恢复继续使用原来的路径。

## 升级兼容

设置 API 不再返回或写入 `balance_forecast_enabled`、`balance_forecast_threshold_hours`、`balance_forecast_max_notifications`。旧客户端提交这些字段时会忽略它们，不影响其他合法设置。邮件模板列表不再提供预测事件，旧预测模板也不能预览或发送；历史通知日志和数据库记录保留。

已经发布的迁移 `331_balance_forecast.sql`、`332_balance_forecast_delivery.sql` 保持原样，不新增删表、删索引或修改账务数据的迁移。旧预测设置、模板、退订记录、episode/outbox 与索引均保留；新安装仍按迁移链创建这些历史结构，但没有运行时代码访问预测表。回退到仍含预测功能的旧二进制前，需要确认旧开关已关闭，否则可能重新启动预测任务。

代码移除不会主动查杀 PostgreSQL 中由旧进程遗留的查询，也不会自动清空已有计费积压。部署时应独立检查数据库会话、行锁与计费恢复状态；PR 合并不代表生产升级。

## 故障依据与范围

2026-11-16 的只读诊断中，余额预测聚合查询持续超过五小时，同时出现用户余额更新行锁等待及应用连接池占满。旧查询收到取消后，自动清理推进，锁等待与资源占用明显回落。这支持移除该后台负载，但不证明它解释了全部延迟，也不保证消除所有高并发计费热点。

回归覆盖旧设置读写、邮件事件目录、现有金额提醒，以及真实设置页面对旧字段的兼容。检查由 CI 执行，截图与当前提交绑定；不通过生产查询、真实发送邮件或付费调用验证改动。
