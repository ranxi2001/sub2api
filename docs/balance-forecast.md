# 余额耗尽预测提醒

管理员在「系统设置 → 邮件 → 余额耗尽预测提醒」配置。默认关闭、提前 12 小时、每个连续预警期最多 3 轮；提前时间为正数且不超过 168 小时，上限为 1–10 的整数。保存设置不发信，full 节点后台每 5 分钟评估，gateway 节点不启动任务。金额提醒独立开关和原有通知路径保持原行为。

## 计算口径

取最近 24 小时、用户创建时间和迁移 331 启用覆盖时间中最晚的起点，到本次 UTC 评估时间（右端不含）。平均每小时消耗 = 此窗口已结算的余额扣款 / 实际窗口小时数；剩余小时 = 当前字面余额 / 平均每小时消耗。金额已经包含实际计费倍率；不使用请求 token 数、账户成本或订阅扣款代替。

至少观察 1 小时、3 份结算收据，首尾收据至少间隔 1 小时。窗口内有无法对应收据的旧路径余额 usage 时，保守不预测；数据缺失和低样本不被解释为零消耗。只接受已应用的 durable billing、已捕获图片款、已结算区域收据，并按用户/请求/API Key 去重。退款/充值通过当前余额体现，不冒充新增消费。

## 通知和幂等

复用已验证且未禁用的通知邮箱、充值链接；同时尊重 `balance.low` 与 `balance.forecast` 的退订偏好。金额提醒当日已经通知过的收件人不再额外收到预测邮件。预测使用独立 `balance.forecast` 中英文模板，可在邮件模板编辑器自定义。不会更改用户余额或发起充值。

预警期状态和 outbox 存入 PostgreSQL，行锁限制多实例每个用户每小时最多一轮。每轮向所有当时符合条件的收件人发送一次，一轮整体占用一次额度；成功、结果不确定或进程中断遗留的 sending 都占额度。明确在 SMTP 之前被关闭配置、取消偏好、缺少模板/邮件配置等抑制的轮次不消耗额度，但仍受一小时间隔限制。关闭再开启、重启或改阈值不会清空历史额度。

SMTP 与数据库不能原子提交。发送出错无法证明邮件未被接收，发送后写状态失败也可能已送达；因此不自动重放不确定轮次，实际成功次数可能少于上限。它是保守的投递上限，不承诺恰好一次或保证送达。进程停止会先等待该任务结束，再关闭数据库。

剩余时长须连续观察至少一小时高于阈值的 120%，才结束旧预警期；之后再低于阈值才新开一期。中间回落或可靠观测间隔超过允许的完整轮转窗口会取消恢复计时，避免阈值附近抖动反复发信。每次扫描至多 2,000 用户，以持久游标轮转；大实例全量覆盖需要多个周期。每轮开始以 3 秒超时的只读计数查询统计符合扫描条件的用户数 N，允许观测间隔为 `(floor(N / 2000) + 2) × 5 分钟`，至少 10 分钟。其中包括候选数恰好为整批时单独归零游标的一轮，以及一轮调度余量；4,000 或 4,001 用户时为 20 分钟。正常轮转不会中断恢复，超过该窗口仍重新计时；持续无可靠样本时保留原额度。
