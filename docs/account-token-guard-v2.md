# 凭证运营

入口：**智能运维 → 凭证运营**（/admin/token-guard-v2）。新安装没有巡检账号，不会自动探测全部账号。管理员通过「添加账号 → OpenAI → 2FA」完成导入后，默认登记到凭证运营并启用巡检、自动重登；已有身份也会登记或更新登录资料。不会自动迁移旧凭证守护中已有的秘密。

## 与凭证守护的区别

- **凭证守护**：按全局或分组配置调用外部测活、重登接口，提供令牌自愈。
- **凭证运营（Credential Operations）**：显式添加账号，逐账号管理登录方式、巡检开关和重登任务；通过模型列表巡检，由独立 Worker 执行持久化重登队列。侧栏与页面使用独立的“凭证卡片 + 循环箭头”图标。

原贡献中使用“凭证守护 V2”作为名称，但该功能不是凭证守护的版本升级或替代。本次统一用户可见名称；页面 URL、API、数据库和内部 `TokenGuardV2` 标识保留兼容，历史截图记录的是更名前界面。

[图标对照预览](https://github.com/ranxi2001/sub2api/blob/297e9201a2f6d6fe70073b370a5b71f49579accf/docs/screenshots/credential-operations/icon-preview.png)：使用实际 `Icon.vue` 组件与中英文文案在隔离预览页渲染，覆盖 16 / 24 / 32 / 64 px、深浅色；仅验证图标，不代表完整页面或后端联调。

## 使用与默认行为

1. 添加现有 OpenAI OAuth 母账号，不支持凭据影子、PAT 或 Agent Identity。
2. 选择邮箱 + 密码（可选 TOTP 长期密钥），或邮箱 + OTP 邮箱 API URL。编辑时留空保留已保存的秘密；切换登录方式会清除旧方式的秘密。
3. 在账号列表的“运行开关”列即时切换“自动巡检”和“自动重登”，修改即保存；账号编辑弹窗仅保存登录凭据，保留已有开关。自动巡检开关控制后续自动巡检；手动巡检、手动重登仍可使用。暂停或移除巡检账号不会取消已经进入重登队列的任务。
4. 在“巡检规则”页配置间隔、阈值和冷却。默认正常巡检 30 分钟、鉴权失败复检 5 分钟、失败阈值 2 次、重登冷却 30 分钟。保存规则后已启用账号立即重新排期；后台每分钟领取一次到期账号，实际时间有调度误差。

巡检读取母账号现有 access token，使用专用原生 Codex 模型列表鉴权请求，不发送付费生成请求。该路径不读取或回填共享目录缓存，不发送条件 ETag，不使用过期缓存兜底或后台刷新，也不把 BPS 混合目录的成功作为母账号鉴权成功；没有本次有效响应的 304 不计为成功。普通模型目录请求仍使用原缓存。401 或明确的令牌拒绝归为鉴权失败；一般 403 归授权拒绝，手机号/安全验证与账号退役不触发自动重登。其余异常归为临时失败。模型列表可访问并不能证明所有生成模型、额度或权限可用。

后台每分钟开始一轮，每个实例使用 3 个独立巡检位，在 90 秒轮次预算内持续处理本轮开始时已到期的账号；每个空闲位只领取 1 个，单次探测预算 30 秒。巡检并发与重登 Worker 并发独立。慢请求仍可能造成积压，页面的“下次巡检”是最早可执行时间，不承诺该时刻完成或所有账号都在一分钟内扫完。

每次领取使用独立租约标识，预算核算、自动重登入队及巡检回写均核对本次租约；旧巡检无法覆盖重新领取后的状态。服务取消或巡检规则读取失败时，以独立短超时归还未完成租约，不改变历史巡检结果、失败计数和下次计划；本轮等待清理结束后才退出。停止服务本身不计为账号鉴权失败。正常探测超时仍按原有临时失败处理。

鉴权失败达到阈值且开启自动重登时，创建持久化任务，由独立 Worker 执行。活跃任务的唯一索引防止重复排队。重登成功前校验账号身份及原凭据快照；原子写回新凭据、完成任务、恢复账号调度并写入调度通知。并发手动编辑或令牌刷新后，旧任务不能覆盖新凭据。

“巡检失败次数”与“重登失败预算”分别计数。页面根据开关、登录资料、活跃任务、失败预算、冷却和鉴权失败阈值显示当前自动恢复阶段；历史巡检异常保留在详情。点击立即巡检或立即重登后立即重新读取状态，不必等待下一次 30 秒页面轮询；规则、账号和运行设置的保存操作互斥，不会打断操作后的回读。冷却截止后，尚未更新的旧冷却原因不再显示为服务不可用。重登任务显示成功后，仍需后续新鲜巡检通过才能证明凭据已恢复。自动重登入队失败的服务日志只记录账号内部编号与固定错误码，不记录上游原文或秘密。

通过 2FA 自动登记时使用 password_totp 和账号代理，加密保存密码与 TOTP。首次登录仍复用外部登录服务，之后的自动重登由程序管理的本地 Worker 处理。导入成功但登记失败时，当前弹窗保留登录结果和输入，重试无需再次登录。

账号只要登记在凭证运营中，旧凭证守护就跳过其自动巡检和重登，并拒绝旧页面的手动重登，包括在凭证运营中暂停的账号。删除凭证运营登记后，账号才可能再次进入旧守护所配置的范围，旧守护仍需自己的登录资料。

## 自动重登服务

Linux amd64 / arm64 上，账密 / TOTP 重登由主程序自动管理。保存账号后，后台按当前应用版本下载 owner Release 中的独立运行包，验证 GitHub 产物 SHA-256，再解压到持久目录的 credential-worker 子目录。运行包自带 Python、Node、TLS 与登录协议依赖，不需要 root 权限、系统包管理器、单独的服务单元、Worker 令牌或手工配置协议路径。

首次准备需要访问 GitHub；准备成功后重启复用本地缓存。运行包独立于主程序，升级后使用对应版本。不可用平台、开发构建或运行包尚未发布时，页面会显示明确原因；下载、启动失败会自动退避重试，不会把“密码已保存”显示为执行服务可用。后台未登记任何账号时不下载运行包。

页面分别显示“凭据加密”和“自动重登服务”状态。准备阶段可以排队，运行服务不可用时手动重登会返回错误。程序停止时回收整个子进程组；异常退出后自动恢复。已领取的持久任务继续沿用超时回收、活跃任务唯一约束、账号身份核对和凭据 CAS 写回。

多实例通过数据库租约领取任务，每个 API 实例管理自己的 Worker，并仅连接对应实例；原有 Mihomo 本地出口语义不变。内部鉴权令牌只保留在当前实例内存和 Worker 环境中，既不要求用户填写，也不作为持久凭据密钥使用。持久凭据加密密钥的备份要求不变。

### 已有独立 Worker

显式配置 OPENAI_REAUTH_WORKER_TOKEN 的部署保留独立 Worker 模式，主程序不会再启动第二个托管消费者。原来的 Worker API、Turb 邮箱 OTP 模式和自定义 toSub2 路径继续兼容。页面显示独立服务是否已经连接；配置过短时明确报告不可用。

只使用密码/TOTP 的旧 systemd Worker 可通过 [一次迁移入口](../deploy/MANAGED_WORKER.md) 转为自动管理：排空任务后运行 `install.sh manage-worker --data-dir <实际持久目录> --drained`。工具固定当前 Release 并校验运行包，保留恢复日志及 key，失败恢复旧服务；切换需要重启一次主 API。迁移完成后，网页升级或安装器升级主程序都会按应用版本选择对应 Worker，无须另行更新 sidecar。

内置运行包仅提供本次验证的 password_totp 模式。邮箱 OTP URL 模式仍由原有独立 Worker 执行；内置消费者只领取密码模式任务，不能误领取或失败掉已有邮箱任务。内置模式下请求邮箱重登会立即返回不支持错误。

### 秘密与验证

密码、TOTP 和邮箱 API URL 加密落库。主程序不会把完整进程环境传给 Worker；数据库口令等无关秘密不会进入登录子进程。凭据与代理沿用已有鉴权通道传递，Worker 令牌不传给第三方登录脚本。运行包与启动失败只回传固定错误分类，进程输出不写入应用日志。

Python Worker 的 --check 不领取任务。运行包发布前需通过 Worker 单元测试、toSub2 离线密码/MFA 测试和重定位运行检查；实际上游登录仍受账号、出口与上游风控影响。运行包构建来源、版本与依赖见 tools/reauth-runtime；不会在用户服务器编译应用或安装系统依赖。

## 迁移与回滚

本 PR 在上游 `production` 的既有 `253` 之后新增 `254`–`257`，不修改已发布迁移：重登配置/任务、凭证运营巡检租约、代理选择。新表仅由管理员显式配置后使用。已有凭证守护账号和设置不变。来自其他 fork 的相同功能若使用不同迁移编号，应单独检查迁移历史，不要直接覆盖已部署迁移文件。

回退二进制不会撤销数据库迁移或删除已保存秘密。停用时先暂停巡检、停止 Worker，等待或处理已排队任务，再回退应用；保留加密密钥及数据库备份。

## 验证边界

后端定向单元测试覆盖身份校验、凭据 CAS、任务归属、加密配置、去重、阈值、规则和停机取消。数据库集成测试使用独立 PostgreSQL/Redis 容器，覆盖新迁移、租约、暂停、过期重领、任务去重和原子写回。前端 Vitest 与合成 API 的浏览器截图只证明页面行为，不代表真实登录已经验证。

Worker 单元测试使用离线协议替身及本地假邮箱；真实密码/TOTP、验证码、外部风控、协议版本兼容性和多实例 Mihomo 部署仍需获准的隔离账号验收。不要使用生产账号、生产数据库或真实对话作为默认贡献验证。

## 即时重登设置

在凭证运营页面上方“凭据加密”区域统一切换重登引擎与本地 Worker 数量，修改即保存。

升级后尚未统一选择引擎时显示“沿用已有账号设置”，保留历史选择；新账号默认本地 Worker。只修改 Worker 数量不改变引擎。显式选择引擎后应用于所有账密 / TOTP 账号的后续任务，邮箱 OTP URL 仍使用本地流程。

可选引擎：

- **本地 Worker（默认）**：保持现有本地 toSub2 登录流程，使用账号配置的代理。
- **Session Studio（临时提速）**：仅适用于密码 / TOTP。经管理员显式选择后，Worker 将该账号的邮箱、密码、TOTP 长期密钥发送到「凭证守护」已配置的 HTTPS 重登地址，复用额外请求头及 `{{uuid}}` 替换。没有单独设置地址时沿用守护默认值。任务仍经过原有账号身份校验、凭据快照 / CAS 和原子写回。

外部服务使用它自己的登录出口，不接收账号代理凭据；选择此引擎时编辑页禁用账号代理选择，已保存的代理配置仍保留，切回本地即可使用。服务失败不会自动切换引擎或重复提交登录。Session Studio 引擎不支持邮箱 OTP URL，切换到邮箱模式时使用本地 Worker。

引擎在 Worker 领取任务时读取。尚未领取的任务使用领取时保存的选项，已经运行的任务继续使用领取时的引擎。暂停 / 恢复巡检和留空秘密的编辑不会清空引擎选择或密码 / TOTP。

需要同时升级 API 与 Worker / 对应版本的内置运行包。迁移 `262_openai_oauth_reauth_engine.sql` 将现有账号默认设为 `local_worker`，不自动向第三方发送凭据。新版 Worker 在领取请求中声明支持的引擎；旧 Worker 只会领取本地任务，不能把外部任务悄悄转为本地。升级前已运行的任务仍应先完成，再更新 Worker。回退旧版本前应将外部引擎账号切回本地并处理活跃任务，数据库新增字段可以保留。

### 本地 Codex 协议阶段诊断

本地密码/TOTP路径继续使用固定 toSub2 提交 `8548397e89bf80e508eda64a87e0d556d43abc84`。Worker 只在任务临时目录建立适配副本：校验精确 callback origin/path、唯一 code/state 与绑定 state、PKCE verifier，然后才交换授权码；三项 OAuth 凭据完整后保留原子文件输出与后端身份/profile/ownership/CAS 校验。授权拒绝不在同一任务内重新登录，不切换引擎或代理。未知依赖布局在登录前拒绝，不静默部分适配。

适配进程只把版本、task_id、白名单 stage/reason 和有限 elapsed_ms 写到任务私有诊断文件；不把 stdout/stderr、异常原文、URL、密码、OTP、cookie 或 Token 当诊断。Worker 有界读取、验证任务绑定及枚举；失败仍要求非零退出/错误结果，`completed` 进度不能替代完整输出。旧运行器没有诊断文件时保留原有退出码/完整输出契约。

任务终态仍是 `failed`，接口新增可选 `diagnostic`（stage/reason/elapsed_ms/exit_code），页面展示安全阶段。Node 的阶段不等于上游业务成功，回写后的巡检复验仍决定账号是否恢复；这不会自动停止、退避或增加自动重登。此功能需要对应 API 与 Worker 生效，不能仅凭源码合并认为线上已升级，也不能从通用 exit1 反推真实故障阶段。

### 自动重登失败预算与递增冷却

巡检鉴权失败次数 `fail_streak` 与重登失败预算分开。迁移 `300_account_relogin_budget.sql` 新增持久化 `relogin_fail_streak`、`last_counted_task_id`、`auto_relogin_exhausted`；升级及首次纳管只以已有终态历史建立水位，不追罚旧失败。每轮巡检按新终态task ID幂等核算并持久化，单批处理最多100条、额外读取一条判断是否有后续页；真实OK可推进半批中的成功水位，但只有完整历史的最终成功才允许清预算，未核算完时拒绝自动追加。重启/多实例不重复计数；乱序或仍活跃的较早任务保留水位并阻止自动追加。

规则沿用现有 `account_token_guard_v2_rules`，新增 `relogin_backoff_max_seconds`（基础冷却至604800秒）与 `relogin_max_failures`（1–20）。旧JSON未提供/提供0时使用保守默认：连续3次、上限 `max(3600, relogin_cooldown_seconds)`，保留既有基础冷却。默认值是本功能设计选择，不是从线上账号反推的用户设定；页面可显式调整，旧客户端保存四项旧字段时保留已设的新预算（必要时提高上限以容纳新的基础冷却），增加上限或切换开关不会隐式清除已耗尽状态。

第n次重登失败的冷却为 `min(基础冷却×2^(n−1), 上限)`，从任务 `finished_at` 起算且不缩短已存在冷却。示例基础60秒、上限240秒：60/120/240/240…；达到连续失败上限后只暂停自动重登。巡检继续、账号/调度/凭据及用户开关不变，不会自动创建手动任务。

保存任务 `succeeded` 还须在其完成后开始的一次巡检返回OK，才清零预算和耗尽状态。`succeeded` 后首次新鲜巡检仍鉴权失败，按一个失败尝试计入预算；单独OK、进度、旧任务成功、早于保存开始的巡检都不能清零。手动重登明确可用，其失败同样幂等计数，不会重新开启已耗尽的自动循环。既有身份/profile/ownership/lease/CAS和任务活跃唯一约束保留。

耗尽行提供“恢复预算（不立即重登）”，需二次确认；API为 `POST .../accounts/:id/resume-relogin-budget`，请求 `{ "confirm": true }`。活跃任务/巡检租约存在时拒绝；成功仅重置预算，保留开关并至少等待一次基础冷却，不缩短现有冷却、不创建任务或恢复账号调度。普通OK或恢复前已计入水位的旧成功不取消此冷却；只有新的成功任务及新鲜OK才可提前清理。后续仍由巡检条件决定能否自动入队。

核算与自动入队在同一事务中锁定账号巡检行及相关任务；手动Codex入队也锁定巡检行，避免与恢复/核算竞争。数据库迁移只增加字段，不改财务数据；旧二进制可忽略字段，但会丧失预算保护，回退前须评估自动化开关。删除纳管记录是显式移除状态，重新纳管以历史水位重新开始。

### 多 Worker 并发

新版消费者默认启动 **3 个独立进程**。页面支持即时调整 **1–16** 个进程，新版 Worker 约每 5 秒通过独立令牌鉴权接口同步：扩容启动新进程，缩容等待当前任务完成后停止领取并退出，不重启整池。临时读取失败时保留上一次数量。Session Studio 任务同样占用进程。

未在页面保存时保留 OPENAI_REAUTH_CONCURRENCY 的既有配置；页面保存后覆盖启动默认值。旧 Worker 无法动态调整数量，需配套升级。--check 只检查配置，--once 仍只领取一个任务。

每个进程有独立 Worker ID、登录会话和临时目录；数据库 `FOR UPDATE SKIP LOCKED`、活跃任务唯一约束和凭据 CAS 继续保护并发领取与写回。并发上限按每个消费者实例计算，多实例的总并发相加。使用现有 systemd control-group 或托管进程组管理整棵进程树；提高并发前按运行环境检查内存上限。

Session Studio 的 JSON / NDJSON 解析一收到终态即返回，不等连接 EOF；响应设置大小和时间边界，拒绝重定向，第三方原始错误及登录输出不写入日志。本地流程在真实执行完成前不再提前上报 `password_submitted` / `mfa_submitted`，避免将整个登录时间误显示为密码阶段停滞。

Session Studio 事件流使用 `type=result` 与对象类型的 `payload` 表示终态；`type=progress` / `heartbeat` 是通知，其中的 `error` 信息或 `active` 状态不结束登录。其他类型不含结果字段的普通通知继续忽略，带 `payload` / `credential` / `error` / `status` 的未知类型则拒绝，避免跳过含义不明的结果。旧版无事件类型的 JSON 结果继续兼容：`credential`、非空 `error` 或明确成功 / 失败状态可结束解析，单独的 `active` / `error=null` 不表示完成。首个终态失败、无效终态或不完整 OAuth 凭据均会拒绝，不会跳过它们接受后续成功；完整凭据仍须经过后端身份校验与 CAS 写回。

客户端现在拒绝重复 JSON 字段，避免后一个同名字段覆盖终态失败；失败任务可展示 HTTP/事件解析/终态/凭据校验/提交的白名单阶段、原因及耗时，HTTP 拒绝显示状态码。这只能说明客户端观察位置，不能证明远端内部 OAuth 失败根因或账号恢复。明确的 models 403 会话/策略拒绝保存 blocked 原因并阻止自动重登，不通过新登录或换会话绕过。源码参考、完整边界和验收 gate 见 [Session Studio 对照说明](reauth-session-studio-reference.md)。

这条临时路径依据仓库现有守护协议实现。离线协议测试不代表外部服务已在线验收，也不保证所有账号都能达到历史守护样本约 10 秒的速度。

统一设置保存于既有 settings 表的 account_token_guard_v2_runtime 项，无新增迁移。历史账号 engine 字段保留用于兼容；回退旧 API 前检查各账号历史 engine 值，因为旧 API 不读取新统一设置。暂停自动巡检不会取消已领取的巡检或已排队的重登。

## 2FA 更换与导出

账号行新增「2FA 管理」，支持管理员手动更换上游 TOTP、验证中断任务和导出新凭据。新密钥先写本地加密恢复日志并确认加密入库，再提交激活；未确认任务阻止重复更换和配置覆盖。独立 Worker 需要配置持久恢复目录。完整流程、备份和回退要求见 [OpenAI 2FA 更换与导出](openai-2fa-rotation.md)。

## 异常原因与历史诊断

最近巡检、最近重登及详情展示安全分类、原操作时间、阶段、短码和人工处理提示。删除/停用合并信号不拆分；未知记录显示未知，原始 provider 文本不回传。最近刷新失败尝试独立展示，后续重试可能已恢复，不代表账号当前状态。协议、旧数据兼容、迁移 309 和跨仓边界见[异常识别说明](credential-operation-errors.md)。
